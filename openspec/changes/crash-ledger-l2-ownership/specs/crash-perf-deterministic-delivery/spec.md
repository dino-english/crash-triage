## MODIFIED Requirements

### Requirement: 投递链路顺序

投递按固定顺序执行，占位符 MUST 在导入前填好。台账镜像不再属于日报投递链路。

#### Scenario: 日报投递

- **WHEN** 日报投递执行
- **THEN** 顺序为：导入日报文档 → 回填索引页中的日报地址 → 导入索引页 → 回填卡片中的详情与索引地址 → 发送卡片
- **AND** 不含台账镜像的导入与地址回填

#### Scenario: 周报投递

- **WHEN** 周报投递执行
- **THEN** 顺序为：导入周报文档 → 回填卡片地址 → 发送卡片 → 追加归档 → 同步台账
- **AND** 台账同步排在卡片发送之后

### Requirement: 文档更新优先于新建

已建立过的文档 MUST 以其记录的地址原地更新，MUST NOT 重复新建。

#### Scenario: 文档台账命中

- **WHEN** 目标文档在台账记录中存在
- **THEN** 原地更新该文档

#### Scenario: 文档台账未命中

- **WHEN** 目标文档在台账记录中不存在
- **THEN** 新建文档并记入台账
- **AND** 输出可直接留档的地址清单

### Requirement: 台账文档采用定点更新

台账文档的更新 MUST 区分可替换区与只追加区， MUST NOT 整份覆盖。

#### Scenario: 更新台账现状表

- **WHEN** Issue 现状表需要刷新
- **THEN** 只替换现状表对应区域
- **AND** 文档其余部分保持不变

#### Scenario: 追加台账时间线

- **WHEN** 本轮产生新的变更记录
- **THEN** 追加至文档末尾
- **AND** 既有条目不被改写

#### Scenario: 定点更新不可用

- **WHEN** 定点更新因定位失效而无法执行
- **THEN** 报错并中止台账同步
- **AND** 不退化为整份覆盖

### Requirement: 投递失败不改变生成链路的成败

投递失败时数据已落盘，MUST 可单独重跑投递补齐；生成链路的退出码 MUST NOT 受投递结果影响。

#### Scenario: 生成成功但投递失败

- **WHEN** 数据生成完成
- **AND** 投递过程失败
- **THEN** 生成链路仍判定为成功
- **AND** 可重跑投递补投
