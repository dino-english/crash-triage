## D1 — CSV 解析：用 Python `csv` 转 TSV，awk 照旧按 TSV 切

三个候选：

| 方案 | 否决理由 |
|---|---|
| SQL 侧改用不含逗号的字段 | 治标：`device.model` 是 Apple 的官方标识符格式，改字段等于丢信息 |
| awk 里手写引号状态机 | bash 3.2 + awk 写 CSV 解析器是典型的自制易错件，且要在三处各写一遍 |
| **Python `csv` 转 TSV** | **采用**——与 L1 `md_csv_table` 同一套解析（`csv.reader`），两条链路口径自然一致 |

TSV 之所以安全：BigQuery 的这些字段不含制表符，而逗号确定会出现。转换后 `awk -F'\t'` 的字段号与原来完全一致，三处调用点只改分隔符。

⚠️ python3 已是既有依赖（`md2docx.py` / `split-fix-list.py`），不引入新东西。

## D2 — 时间线幂等：按「正文」查重，不按整行

条目形如：

```
- 2026-08-22：🆕 [Android] 新增 [libcutils.so]（1 事件） · [周报](https://...)
```

同一条目在不同轮次的**链接不同**（未投递时是 `__REPORT_URL__`，投递后是真 URL），整行比对查不出重复。查重键取 ` · [周报](` **之前**的部分。

⛔ 不用「日期 + 平台」做键：同一天同一平台可以有多条不同 issue 的条目，那样会误删。

## D3 — 未投递时不写悬空占位符

`__REPORT_URL__` 的回填在 `deliver.sh`，发生在本地台账写入**之后**。NO_DELIVER 或投递失败时回填不发生，占位符就永久留在台账里——它既不是链接也不是「无链接」，读者点了没反应。

改法：写入本地台账时若本轮不投递（`CRASH_REPORT_NO_DELIVER=1` 或 DRY RUN），条目**不带链接后缀**。投递路径行为不变。

⚠️ 反过来「先投递再写台账」不可行：台账内容要先渲染出来才能作为投递物之一同步到飞书，顺序不能倒。

## D4 — L2 生命周期基准与 L1 分离

⛔ **不复用 L1 的 `issue_seen`**。L1 取数走 `crash-issues.sql`（**带版本过滤**，只看最新 2 版），L2 走 `crash-issues-all.sql`（**刻意不带版本过滤**，台账要跨版本追踪生命周期）。老版本上仍在发生的 issue 从不进 L1 基准，复用会让它们每周都被标成「🆕新增」——比现在的「全是遗留」更糟，因为它是**错的**而不只是缺的。

L2 自有基准 `$STATE/issue-seen.json`：

```json
{"<32位id>": {"first": "2026-08-19", "last": "2026-08-24"}}
```

- **判定**：无记录 → 🆕新增；`last` == 上一轮日期 → 🔁遗留（连续出现）；有记录但 `last` 早于上一轮 → **🔁回归**
- **「上一轮」取基准里的最大 `last`，不是「上周」**——照抄 L1 踩过的坑（`crash-daily.sh:830`）：漏跑一周时按「上周」判定会把全部 issue 误判成回归
- **保留 90 天**，与 L1 同期限；超期条目清理，再出现按新增处理（spec 要求基准保留期有界）
- **首轮基准为空 → 不标任何态**（spec 硬要求，且与「首轮只建基线不标新增」同源）

`first_seen` 改为优先取基准的 `first`，回退到上一版表格解析值，再回退到今天。这同时修掉「issue 消失后再回来被记成今天首次纳入」。

⚠️ 新增基准文件 MUST 登记进 `bin/test/artifacts.sh` 的 `artifacts_baseline_files()`——不登记则等价性验收的快照回滚协议不还原它，第二次跑批看到的是热基准，两次走不同分支（该协议头部注释已写明这个失效模式）。
