## Why

报告能回答「崩溃了多少次」，回答不了**「谁受影响、集中在哪、什么时候」**——而后三个问题才决定要不要今天就修。

实测（Android，近 14 天，FATAL + ANR）：

| 机型 | 事件 | 受影响安装 | 集中度 |
|---|---|---|---|
| OPPO CPH2591 | 14 | 7 | 2.0 |
| **Google Pixel 8 Pro** | **9** | **1** | **9.0** |
| Xiaomi 25028RN03A | 8 | 5 | 1.6 |

按事件数排序，Pixel 8 Pro 是第二严重。按影响人数看，**它只影响一个人**——极可能是某台测试机或某个用户的特定环境。当前日报的 issue 明细表只有「事件数」一列，**这两者长得一模一样**。

同样看不到的还有：

- **OS 版本分布**：Android 16 贡献 51 事件 / 44 安装（集中度 1.16，分布广），Android 11 只有 16 / 12。是新系统适配问题还是全版本通病？报告答不了。
- **时段分布**：峰值在 14:00 与 21:00（各 19 事件）。均匀分布的常态崩溃与某一时刻的尖峰是完全不同的故障——后者往往对应一次发版、一次配置推送或一次后端异常，**是可以立刻行动的信号**。
- **并发聚集**：同一分钟内的事件堆叠是「一次事故」，摊在两周里的同样数量是「一个慢性问题」。

这些维度**全部已在 BigQuery 表里**（`device.manufacturer` / `device.model` / `operating_system.display_version` / `event_timestamp`），一次 `GROUP BY` 的事。现有 SQL 用了表中约 110 个字段里的 6 个。

## What Changes

- **日报新增「一、汇总」段**，报告结构变为 **汇总 → 版本对照 → 明细**（当前的「一、结论」并入汇总）。
- 汇总段**只回答三个问题**，每个问题一小块：
  1. **影响多少人** —— 受影响安装数、集中度（事件 / 安装），双端分列
  2. **集中在哪** —— 机型 top N、OS 版本 top N，各带事件数 / 安装数 / 集中度
  3. **什么时候** —— 时段分布峰值；并发聚集检测（短时间窗内的事件堆叠）
- **issue 明细表增「安装数」与「集中度」两列**，并**改按影响安装数排序**（现按事件数）。
- **集中度异常的 issue 显式标记**：集中度远高于该端均值时标注「高度集中，疑似单设备/单环境」，避免它挤占注意力。
- **周报同步**：主力版本段增机型 / OS top3，用于跨周对比适配面变化。

## Non-goals

- **不做全维度下钻**。汇总段是「一目了然」，不是数据倾倒。每个维度只给 top N（N 默认 3–5），不做维度交叉（机型 × OS × 时段的笛卡尔积属于排查工具的范畴，不是日报）。
- **不把维度塞进版本对照表**。那张表已有 9 行 × 2–4 列，加维度必然溢出。维度只在汇总段出现。
- **不做根因推断**。汇总段给的是「可定位对象」与「下一步取证方向」，不给结论——与既有的性能段硬约束一致（L1 只呈现，不分析）。
- **不改崩溃率、崩溃次数的口径**。
- **不引入设备画像的长期存储**。汇总是当轮快照，不进 `metrics-history.jsonl`（那里存的是可做趋势的标量，机型 top N 不是）。

## Capabilities

### New Capabilities

- `crash-perf-impact-summary`：崩溃影响面的汇总呈现——受影响规模、集中度、机型与系统版本分布、时间分布与并发聚集，以及「按影响人数而非事件数排序」这一排序口径。

## Impact

| 文件 | 变更 |
|---|---|
| `bin/sql/crash-dimensions.sql` | **新增** —— 机型 / OS 版本 / 时段分布，按平台与版本 |
| `bin/sql/crash-issues.sql` | 增 `COUNT(DISTINCT installation_uuid)` 列（明细表的安装数与集中度） |
| [bin/crash-daily.sh](../../../bin/crash-daily.sh) | 新增汇总段渲染（卡片 + XML + markdown 三处）；明细表增两列并改排序 |
| [bin/crash-weekly.sh](../../../bin/crash-weekly.sh) | 主力版本段增机型 / OS top3 |
| `CLAUDE.md` | 报告结构说明更新为「汇总 / 版本对照 / 明细」 |

**与 `crash-error-type-coverage` 的关系**：该 change 把 ANR 与 NON_FATAL 纳入统计。**建议其先落地**——汇总段的影响面理应覆盖 ANR（实测 ANR 事件量与崩溃持平）。若本 change 先做，汇总段只覆盖 FATAL，后续需补一轮。

**风险**：汇总段是版面增量最大的一次改动，卡片空间有限。卡片只放「影响多少人 + 最集中的一个维度」，完整三块进文档——CardKit v2 的 table 组件无行级样式，堆多了不可读。
