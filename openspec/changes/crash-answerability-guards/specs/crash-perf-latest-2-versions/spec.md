## MODIFIED Requirements

### Requirement: 告警判定对象回退

告警与摘要行的判定版本默认取最新版；**当最新版无法回答所判定的问题时** MUST 回退为
该端会话量最大的版本。判定 MUST 一次算出、全部指标共用（⛔ 不引入每指标一套判据）。

「无法回答」MUST 覆盖以下两类，任一成立即回退：

1. **样本量撑不起阈值**：会话数 < 1/最严比率阈值。理由：比率要能回答「有没有超过 t」，
   至少得让单个事件落在 t 附近，即 n ≥ 1/t。2026-09-04 实测反例：45 个会话时 1 个 ANR
   即 2.22%，是阈值 0.47% 的 4.7 倍——该样本量下指标只能读出 0% 或 ≥2.2%，
   **无法表达「刚好在阈值上」**，于是恒为 0.00% 看似健康。
2. **该版本无性能数据**：性能批量表滞后约 2 天，新版在其中常年零行，此时 6 个告警指标中
   有 4 个直接无解。⛔ 原设计认为「值为空则本就不告警，方向正确」——该假设在**表滞后**
   面前不成立：空不是因为样本小，而是表未同步，「不告警」等于整个指标无人监控。

⚠️ 判定输入取不到时 MUST NOT 回退——宁可维持既有行为，也不因取数失败静默换判定对象。
⚠️ 无可替代对象（会话量最大者就是最新版）时 MUST NOT 回退。
⚠️ 本要求只影响**判定对象**，MUST NOT 改变表格呈现——各版本列一列不少。

#### Scenario: 最新版会话数不足以分辨阈值

- **WHEN** 最新版会话数低于阈值可分辨所需的样本量
- **THEN** 判定对象回退为会话量最大的版本

#### Scenario: 最新版会话数充足但无性能数据

- **WHEN** 最新版会话数达标，但其性能数据状态明确不可用
- **THEN** 判定对象同样回退——否则该端性能类告警整体失效

#### Scenario: 回退原因的呈现

- **WHEN** 发生回退
- **THEN** 摘要行 MUST 说明判定对象与**该端各自的真实原因**
- **AND** ⛔ MUST NOT 写死单一原因——存在多种触发条件时，写死一种会把另一种说成假原因
- **AND** 跑批日志 MUST 只列真正发生回退的那一端

#### Scenario: 稳态不受影响

- **WHEN** 最新版会话数充足且性能数据可用
- **THEN** 判定对象仍是最新版，行为与回退机制引入前等价
