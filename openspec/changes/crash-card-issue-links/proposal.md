## Why

`crash-report-issue-identity` 给三份产物的 issue 条目都加了控制台直达链接，但对卡片下了
「MUST NOT 附外部链接」的禁令，理由写的是**「卡片单元格宽度有限，链接会挤占并触发截断」**。

2026-09-01 实发一张测试卡片到开发机私聊实测，**这条理由只对了一半**：

| 卡片里的载体 | 链接可点 | 列宽影响 |
|---|---|---|
| `{tag:"markdown"}` 块 —— **周报段一（本周变化）就在这里** | ✅ 可点 | **无变化** |
| `{tag:"table"}` 单元格（`lark_md`）—— 主力版本表 / 日报明细 | ❌ 不可点 | 判读不了（多半渲染成字面 markdown） |

原判断把**裸 URL**与 **markdown 链接**混为一谈了：`[2a800b33](url)` 只显示锚文本 `2a800b33`，
与纯文本一样宽，⛔ 根本不存在「挤占列宽」。

代价是实打实的：**卡片是群里大多数人唯一会看的东西**，而段一每条变化的 issue id 现在只是灰色文本，
想下钻必须先点开周报文档再找那一行。最该能点的地方反而不能点。

## What Changes

- **周报段一在卡片里改为带链接**（`sec()` 的卡片调用由 `want_link=0` 改为 `1`）。
  ⚠️ 段一在卡片里的载体是 markdown 块，与文档共用同一个 `sec()`，一个定义点两次调用的结构不变。
- **表格单元格保持无链接**（主力版本表、日报明细的卡片侧）——实测不可点，且字面 markdown 会撑宽。
- spec 的「卡片中的 issue 条目」场景按载体拆开，⛔ 不再一刀切禁止。

## Non-goals

- ⛔ **不改文档侧**（已按 `crash-report-issue-identity` 交付且验过）。
- ⛔ **不试图让表格单元格可点**——实测 CardKit 表格不支持，绕过去只会渲染出字面 markdown。
- ⛔ **不追加 `crash-report-issue-identity` 的归档内容**：归档的 change 不改写，本 change 即是它的勘误。

## Capabilities

- `crash-perf-daily-weekly-report`（修改）：「issue 级条目提供外部下钻入口」的卡片场景按载体拆分。
