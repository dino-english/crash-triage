# 实施中发现

## F1 ⛔ 灰度关联不可用——「字段存在」不等于「有值」

我此前把 `remote_config_feature_rollouts` 评为「价值最高的后续候选」，**依据只是它出现在表结构里**。
实测近 30 天 **201 个崩溃事件中带 rollout 信息的有 0 个**。

**推荐撤回。** 教训：看到字段就推断可用，是把 schema 当成数据。查一次 `COUNTIF(ARRAY_LENGTH(x)>0)` 只要几秒。

## F2 归因维度实测有区分度，且最有价值的是「反直觉」的那一行

Android 1.5.3 近 7 天：

| owner | library | 事件 | 影响安装 |
|---|---|---|---|
| **系统** | **com.prime.dino.english** | **30** | **18** |
| 自家代码 | com.prime.dino.english | 16 | 12 |
| 三方 SDK | com.prime.dino.english | 10 | 8 |

**归因方是「系统」，被归因的库却是自家包名**——那是系统帧被自家代码调用。
只看 owner 会读成「系统问题与我无关」，只看 library 会读成「自家代码崩了」，两者都不对。
所以 SQL 与呈现都强制两列同出，且 spec 写死「不得表述为非自家问题」。

## F3 L1 的新增判定原本是死的

`daily-snapshot.json` 的 `ios_ids` / `android_ids` 来自 MCP，而 MCP 抓取长期失败——
**两个数组都是空数组**。也就是说 L1 的「新增 issue」告警从来没有真正生效过。
改用与崩溃统计同源的 BigQuery issue id 后一并修复。

## F4 ⚠️ 我埋的一个 bug：BigQuery JSON 的数字是字符串

集中度 `.n / .users` 直接算，报 `array (["2"]) and number (10) cannot be multiplied`——
**BigQuery 的 JSON 输出把所有数值都给成字符串**。必须 `tonumber`。

这个 bug 在加集中度那一批就埋下了，直到本轮才炸——因为它只在 issue 明细表**有行**时触发，
而此前几轮 iOS 零崩溃、Android 的表恰好没走到那条路径。

## F5 ⚠️ 函数定义顺序 / sed 删行 两个低级错误

- `card_focus_line` 调用 `blame_top`，而后者定义在**调用点之后** → `command not found`。
  bash 函数定义顺序不重要，但**定义必须早于调用发生的时刻**。
- 全版本 crash-free 用 `sed '/version IN ({{VERSIONS}})/d'` 删版本过滤行——
  **sessions 子查询里那行就是 `WHERE ...` 本身**，删掉留下 `FROM ... AND` 语法错误。
  改成把条件替换为 `TRUE`。

两处都触发了 ERR trap，往私聊发了一条误告警（开发机身份，未进群）。

## 验证结果

- 生命周期三态：首轮 13 条建基线**无任何新增标记**（正确）；第二轮 13 长期 + 1 回归
  （人工把一条的末次日期改早两天，被正确识别为 `🔁回归` 而非 `🆕新增`）
- 全版本 crash-free：iOS 100.00% · Android 99.29%（与手算 99.28% 一致）
- 卡片新增三行 markdown（影响集中 / 系统版本最差 / 归因），**表格行数未增加**

## F6 版本门槛把最新版静默剔除——由使用方发现

`latest-versions.sql` 原有 `HAVING sessions >= 5`（1 天窗口），本意是滤掉「个位数会话的灰度/内测残留」。
但它同时会滤掉**刚开始放量**和**放量被叫停**的新版——两种最该被看见的情况。

实测：Android 1.5.4 最后一个会话是 **2026-08-21 11:27 UTC**，此后 1 天窗口 0 个会话
（7 天总共 36 个）。于是「最新 2 版」自动滑到 `1.5.3 → 1.5.1`，**卡片上没有任何一句话
说明 1.5.4 存在过**——使用方早上还看到它，晚上就没了。

对比同一套系统里的其它缺数处理：性能停更说「⚠️ 数据未同步（截至…）」、版本解析失败说
「⚠️ 版本解析失败」。**唯独「最新版掉出门槛」是完全静默的。**

**处置**（使用方拍板）：直接去掉门槛。小样本由 `SAMPLE_SESSION_MIN` 在单元格打「⚠️」标出。
去掉后两端恢复 `1.5.4 / 1.5.3` 且对齐，Android 1.5.4 显示 `91.67% (3/36) ⚠️`——
数字本身没意义，但**它存在这件事可见了**。

**残余风险（刻意接受）**：版本号更高的内测包哪怕 1 个会话也会成为「最新版」。
实测当前两端最高版本就是 1.5.4，其上无噪声版本。真被内测包刷屏时再定更精确的规则，
**现在不预先造**。
