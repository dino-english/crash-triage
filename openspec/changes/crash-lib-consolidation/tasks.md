## 3. SQL 包装收口

⚠️ **实施中修正了原设计**：原打算收口成 `q_dim` / `q_crash` 等**整套包装函数**，读代码后发现不对——
L1 与 L2 对同一份 SQL 的调用约定**确实不同**（L1 多走 `bqq json` + jq 取字段，L2 走 `bqq csv` + cut/awk），
那是刻意的差异不是重复。强行统一会把两条链路的输出格式绑死，反而制造耦合。

**真正重复的是占位符替换链**——8 份 SQL × 两条链路的 sed 链。实证：2026-08-24 加 `{{FG_NORM}}`
时必须改两处，漏一处的表现是 BigQuery 语法错（响，但要等到跑批才响，且错误信息里没有「哪个占位符漏了」）。

- [x] 3.1 新建 `bin/lib/query.sh`，只提供 `q_render <sql> KEY=VALUE...`——渲染 SQL 文本到 stdout，
      调用方自己决定喂 `bqq csv` 还是 `bqq json`
- [x] 3.2 ⛔ **不设窗口默认值**：L1 用 `CRASH_DAYS`(7)/`PERF_DAYS`(3)、L2 用 `WEEK_DAYS`(7)，

      「加了新占位符只改一条链路」最常见的落地方式，现在在调用点就拦下并指名文件与占位符
- [x] 3.4 ⚠️ 替换用 python 字面替换而非 `sed`：值里出现 `|`（sed 分隔符）或 `&`（整段匹配）会被

  故不在本条字面范围内）还留着 3 段 sed，而它与 L1 **共用** `crash-nonfatal-issues.sql`。
  ⛔ 那正是本 change 要消灭的失效模式，且这一处的失败形态比当初记录的更糟——
  当初是「响，但要等到跑批才响」，这里**不响**：占位符没替换 → BigQuery 语法错 →
  `bq_json` 按设计返回 `[]` → **台账 NON_FATAL 现状表悄悄清空**。故一并收口。

  ⛔ `nonfatal_rows()` 不是简单替换：它原先先把 `{{VERSIONS}}` 换成哨兵、再用 sed **删掉整行**，
  以此实现「台账跨版本追踪，刻意不加版本过滤」。改法是把该行变成**整条谓词占位符**，
  由调用方传完整过滤或空串——「故意不过滤」从一条 sed 表达式里的隐含行为，变成 SQL 文件里的显式契约。
  ⚠️ 顺带记一坑：SQL **注释里不能写占位符字面量**，`q_render` 是全文字面替换，会把注释里那处也换掉。

  收口后全仓裸 sed 占位符替换 **0 处**。三条渲染路径均过 `bq --dry_run`，漏传 `VER_FILTER` 仍当场失败。
- [x] 3.6 等价性验收（2026-08-27），⚠️ **分三层证，因为最外层这次天然证不了逐字节**：

  **① SQL 层（最强，构造性）**：把新旧渲染结果去 SQL 注释、压空白后比对——
  台账路径 / 日报路径 / `crash-issues-all` **三条全部逐字符一致**。
  BigQuery 收到的是语义完全相同的查询，结果一致是构造出来的，不依赖运气。

  **② 子进程产物层**：`fetch-snapshot-bq.sh` 新旧各跑一次，`snapshot.json` **逐字节一致**（5668 字节）。
  ⚠️ 这条尤其有说服力：`crash-nonfatal-issues.sql` 文件变了（加了注释）→ 缓存键不同 →
  新代码那轮**真去查了 BigQuery**，结果仍与旧代码的缓存结果逐字节相同。
  （`crash-issues-all.sql` 文件未变，sed 与 `q_render` 都是字面替换 → 渲染文本相同 → 缓存命中。）

  **③ L1 整跑层**：新旧共享冻结缓存各跑一次。⛔ **拿不到逐字节一致，原因是构造性的**：
  改动往 SQL 里加了注释 → 文本变了 → 缓存键必然不同 → 那两份 SQL 只能走活数据。
  归一化掉跑批时刻 / RUN_ID / 沙箱路径后，整份日报只剩 **1 行**差异：
  同一 issue、同标题、同 86 个受影响安装、同最新时间，只有事件数 `586` → `583`。

  背靠背复验证明它是时间漂移不是回归：把**新旧两份渲染 SQL 现在同时跑**，两边都返回 **597**——
  而 597 ≠ 586 ≠ 583，说明这个数随墙上时钟走（滚动窗口下界 `NOW − 7 DAY` 每分钟都在推进）。

  ⚠️ 教训记一笔：**「改了注释」就足以让冻结缓存失效**。等价性协议里「同缓存严格 diff」的前提是
  SQL 文本一字不动；一旦动了注释，就必须补 ① 那种语义层证明，否则活数据漂移会被当成回归
  （或者更糟——真回归被当成漂移放过去）。
