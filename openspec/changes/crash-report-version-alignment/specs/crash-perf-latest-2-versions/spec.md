## MODIFIED Requirements

### Requirement: 周报承接主力版本视角

周报 SHALL 新增主力版本放量段。主力版本集合 MUST 为「窗口内会话量 top2」与「最近一天会话量 top1」的并集，上限 3 个版本。

每一列 MUST 标注其入选理由（窗口主力 / 当日主力），MUST NOT 一律标注为「主力」。

理由：单一的窗口累计会话量是滞后积分量，在版本交替期会系统性选中正在退役的版本。实测 2026-08-31：Android 1.5.6 当日会话 855（占 93%），7 天累计 1819 落后于 1.5.5 的 2064，因而未入选——周报三段主体整体描述了当日合计仅 66 个会话的两个版本，而 1.5.6 上的 3 条 FATAL issue 一条未呈现。

#### Scenario: 主力版本按会话量选取

- **WHEN** 生成周报放量段
- **THEN** MUST 按会话数降序取窗口内 top2 版本
- **AND** MUST 显式标注与日报口径的差异（日报=最新 2 版，周报=主力版本）

#### Scenario: 新版本正在放量

- **WHEN** 某版本在最近一天的会话量居首，但不在窗口累计 top2 内
- **THEN** 该版本 MUST 补入主力版本集合
- **AND** 该列 MUST 标注为当日主力
- **AND** 其余列的取值与口径 MUST NOT 因此改变

#### Scenario: 两个集合重合

- **WHEN** 当日 top1 已在窗口 top2 之内
- **THEN** 主力版本集合为 2 个版本
- **AND** 呈现形态与未启用本要求时一致

#### Scenario: 补入的版本样本很小

- **WHEN** 当日 top1 版本的会话量低于小样本阈值
- **THEN** 该版本仍 MUST 补入，并由既有小样本提示标注
- **AND** MUST NOT 因样本量门槛将其剔除
- **AND** 理由：与「不设会话数门槛」同源——门槛会静默剔除刚放量或被叫停的新版，而那正是最该被看见的时刻

#### Scenario: 摘要行的判定对象

- **WHEN** 摘要行呈现某项指标的判定结果
- **THEN** MUST 标明该结果所属的版本及其入选理由
- **AND** 理由：与小样本回退必须在摘要行说明同一条纪律——换了判定对象却不说，比漏报更难排查
