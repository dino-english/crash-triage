## Why

告警判定固定看**最新版本**（既定口径：「上一版与主力补充列只着色不告警——既定事实拦不了发版」）。
这条规则在稳态下是对的，但在**新版放量窗口内同时制造漏报与误报**——而放量窗口恰恰最需要准确告警。

2026-08-22 同一次跑批的实测：

| | 版本 | 会话数 | 值 | 告警 |
|---|---|---|---|---|
| **漏报** | Android 1.5.3（主力） | 6600+ | ANR 率 **0.71%** 🔴 | ❌ 不告警 |
| | Android 1.5.1 | 1700+ | ANR 率 **0.86%** 🔴 | ❌ 不告警 |
| | Android 1.5.4（最新） | **1** | ANR 率 0.00% | 摘要行只看它 |
| **误报** | Android 1.5.4（最新） | **36** | 崩溃率 **8.33%**（3/36） | ✅ 触发红档 |

`8.33%` 来自 3 次崩溃除以 36 个会话——统计上无意义；而 6600 个会话上的 0.71% ANR 真实超标却沉默。
**同一条规则，同一次跑批，两个方向都错。**

## What Changes

- **告警判定版本**改为：默认最新版；当最新版会话数低于小样本阈值时，**回退到该端会话量最大的版本**。
- 判定版本仅影响**摘要行与告警**，不影响表格呈现——表格仍按既有版本列全部呈现，一列不少。
- **回退必须可见**：摘要行标注判定对象是哪个版本，并说明为何不是最新版。
  否则读者会困惑「为什么在报一个旧版本」。

## Non-goals

- **不改「上一版只着色不告警」的初衷**。该口径的本意是「既定事实拦不了发版」——
  本 change 不推翻它，只是补上「最新版样本不足时它代表不了线上」这个前提缺口。
- **不改阈值**。
- **不为性能指标单独设样本判据**。性能指标的样本量其实是 trace / screen 样本数而非会话数，
  但两者同向（新版会话少则性能样本也少），且性能指标已有自身的「样本不足 → 空值 → 不告警」保护。
  统一用会话数做判据，简单且方向正确；差异记录在 design。

## Capabilities

### Modified Capabilities

- `crash-perf-latest-2-versions`：修改「阈值与小样本提示作用于最新版」——增加小样本回退规则。

## Impact

| 文件 | 变更 |
|---|---|
| `bin/crash-daily.sh` | 新增判定版本解析；6 个 `red_line` / `yellow_line` 调用点的取值改用判定版本；摘要行增回退标注 |

**影响范围**：全部 6 项告警指标（崩溃率 / ANR 率 / 慢帧最差页 / 冻结率 / 启动 P95 / 接口错误率）。
稳态下（最新版会话数充足）行为**完全不变**。
