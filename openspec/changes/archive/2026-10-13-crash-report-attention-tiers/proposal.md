## Why

日报、周报的卡片与文档**把「该谁、今天做什么」埋在了数字下面**。2026-10-11 用生产产物逐条核：

| 现象 | 实例（生产） |
| --- | --- |
| 日报卡片 4 条 🔴 全是慢性状态，每天一样 | 10-11：慢帧最差页 / 冻结率 / 启动 P95 / 「7 个已修未发版」 |
| **真正要开发重修的 issue 一个字没出现** | 10-11 fixmap：`85c581ed` `62f88f39` `4d05f9e7` 状态「修了仍在」（新包事件 10 / 5 / 9），日报只数「已修未发版」 |
| **本周第一的崩溃在卡片上没有名字** | Android 1.8.2 `8bc4b97e` LINE SDK 7 天 10 台，已修未发版——卡片只写「7 个 issue」 |
| 两端合用一盏灯，健康的一端被陪着标红 | `🔴 慢帧最差页 iOS 1.8.2 45.1% · Android 87.8%`：iOS 45.1% 是黄档（`SLOW_FRAME_RED=50`） |
| 「最差页」当大盘灯，单页不改就永远红 | Android Splash 87.8% / 冻结 5.2%；平台整体 3d 实为 43.6% / 0.51%（2026-10-11 实查） |
| 红灯只说「红」，不说哪部分拖的、是不是新问题 | Android 启动 P95 2231ms：Android 11 及以下占 9% 样本、贡献 43% 慢启动；P95 逐版从 ~3.5s 降到 2.1s（老问题、在改善） |
| 周报模型排好的 P0/P1 在文档第 251 行后，卡片上没有 | 10-05 周报：卡片是 27 行状态平铺（含 15 行已关闭 / 消失），commit 正文整段贴入 |

用户诉求（2026-10-11）：卡片与报告**把紧急和观察区分开、高亮重点**；需要开发修的紧急 bug 要一眼可见。

## What Changes

日报与周报的卡片、文档统一成**三档 + 健康度**的呈现：

| 档 | 含义 | 日报判定 | 周报判定 |
| --- | --- | --- | --- |
| 🚨 **紧急 · 开发要修** | 今天/本周要有人动代码 | 确定性规则（修了仍在且近 7 天有事件 / 新增·暴涨·回归 ≥2 台 / 长期未修 ≥5 台 / 崩溃率红档 / 性能版本退化） | 分析层产出的 **P0/P1**（新增机器可读契约），失败回落日报规则 |
| ⏳ **等发版**（日报）/ 🔧 **修复进度**（周报） | 代码已修，等上线 / 修复是否生效 | 已修未发版，按 7 天影响台数排序并**列出 id** | 修复四态计数 + 修了仍在明细 |
| 👀 **观察** | 今天不用动 | 其余：少量未修、性能长期超标、已发版待验 | P2 与其余 |

- **卡片版式**（2026-10-11 实发验证，见 `mockups/`）：🚨 每条一个色底块 + 「控制台」按钮 + 一句「为什么」；次要列表收进**折叠面板**，面板内用 **markdown 表格**（table 组件不能进折叠面板、单元格不渲染链接）；标题栏颜色与计数标签随最高档变化。
- **健康度面板**：取代现卡片单表。两端分列，**灯按平台分判**；只给超阈值的数字上色。
- **慢帧 / 冻结的判灯口径**：由「最差页单页」改为**平台整体 3d 值**（与现 1d 平台级同算法），最差页降为下钻线索。
- **红灯下钻**：亮红的指标在卡片附一张横向条形图 + 一句结论 + 一句历史（启动 P95 → 系统版本分桶；慢帧/冻结 → 页面；接口错误率 → 接口；崩溃率 → issue）。
- **文档**：首屏换成「今日要点 / 本周必修」三档，issue 明细加「分档」列；数据层段落与分析层段落**一个不少**，只调顺序。
- **周报分析层**新增产物 `priorities.json`（P0/P1/P2 + issue id + 一句动作），脚本校验后驱动 🚨；不合规即回落并显式标注。

## Capabilities

### New Capabilities

- `crash-perf-attention-tiers`: 三档分档的判定规则（日报确定性 / 周报分析层契约 + 回落）、健康度面板、红灯下钻、卡片组件选型。

### Modified Capabilities

- `crash-perf-daily-card-v2`: 「单表承载」「顶部摘要」「纯展示层红线」退役；红绿灯改为按平台分判、慢帧/冻结改平台整体值；影响集中信息允许进折叠面板；保留项中的「三层结构」改为三档 + 健康度，深色自适应扩到图表与色底块。
- `crash-perf-daily-weekly-report`: 「告警判定」改为分档判定；「周报文档构成」允许首屏摘要引用分析层优先级（分析层段落原样保留）；「issue 级条目提供外部下钻入口」补 markdown 表格载体。

## Impact

**代码**

- `bin/crash-daily.sh`：新卡片构建（替换 `build_card_table()` 单表与摘要行渲染）；分档判定调用；健康度面板；下钻图；文档首屏与明细「分档」列。⚠️ `ROW_DEFS` 别名 3 处调用点（口径文档 :391-434）——文档路径必须保持完备。

- `bin/fetch-snapshot.sh`：full 模式 prompt 增加 `priorities.json` 产物契约；⛔ 不得把它加进成功判据（缺失只降级）。
- **新增** `bin/lib/core/tier.sh`（纯函数：分档判定、按平台判灯）与夹具。
- **新增 / 改** SQL：`perf-screens` 平台整体 3d 值；`perf-startup-by-os.sql`（启动按系统版本分桶）。占位符只替换值。
- `bin/md2docx.py`：三档 callout 上色（红 / 橙 / 灰）。

**文档**：`docs/CLAUDE-架构与数据口径.md`「卡片的能力边界」「卡片：单表」「摘要行」三节按新版式改写（保留其踩坑记录）。

**查询成本**：L1 每端最多 +2 条（平台 3d 值恒跑；下钻只在亮红时跑），L2 同量级。

## Non-goals

- ⛔ **不改既有阈值数字**（`CRASH_RATE_RED` 等原样）；只新增分档阈值（Q2）与性能退化门槛（Q3）。
- ⛔ **不改数据源与取数窗口**；不改修复四态判定（change `crash-fix-release-status` 已定）。
- ⛔ **不改台账**（结构、同步、生命周期均不动）。
- ⛔ **不改流水线故障告警卡**（`bin/alert.sh`）——用户确认其已足够简洁。
- ⛔ **不在本 change 修两个已知数据缺陷**（另起修复，见 design「顺手发现」）：周报「入选」列串入设备数；`d0dcb015` 的 docs 提交被当成修复。
- ⛔ 渲染层拆分与表名参数化仍是刻意的 Non-goal（CLAUDE.md）。
