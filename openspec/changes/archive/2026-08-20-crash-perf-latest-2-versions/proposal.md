## Why

日报当前是**全版本聚合**：崩溃/性能/放量三段都不分版本。实测（2026-08-17，bq 实跑）iOS 崩溃 7 天窗 280 事件里 260 次来自 1.5.2，而线上会话量最大的已经是 1.5.4 / 1.5.3——**读日报的人看到的是历史包袱的均值，不是当前发出去的版本的质量**。发版质量回归（新版比上一版差）在聚合口径下完全不可见。

同时四处呈现已被反馈「读不动」：日报卡片（全平台聚合，无版本维度）、日报文档（三段平铺、口径注释淹没数据）、周报卡片与周报文档（只有变化列表，无放量分母）、`reports/LEDGER.md` 台账（单张宽表被拉得极长，列多到需要横向滚动）。

## What Changes

**口径（日报）**

- 日报三段（崩溃 / 性能 / 版本放量）**全量按「最新 2 个版本」过滤**，不再输出全版本聚合值。版本定义 = 该端 `firebase_sessions` 里**版本号最大的 2 个 `display_version`**（`sort -V`，非会话量排序），门槛 `MIN_SESSIONS`（默认 5）滤掉噪声版本。
- 每个数字**按版本分列**呈现，不做两版合计——避免引入第三套口径。
- **主力版本补列**：若「会话量 top2」中有版本不在最新 2 版内（新版刚放量、大盘还在旧版的典型情形），该版本**追加为补充列**并标注「主力」，列集合上限 4（最新 2 ∪ 主力 2）。两者重合时（当前常态）卡片形态与不开此特性完全一致。
- 新增**版本间对比**指示器：最新版相对上一版的增减（↑ 变差 / ↓ 变好 + 红绿着色），这是本次的核心可读性诉求。
- 新增「该版本无数据」态，与既有「数据未同步」态**严格区分**：表在窗口内有数据但该版本 0 行 → `— 该版本无数据`；表整体 0 行 → 沿用 `⚠️ 数据未同步，最新截至 X`。性能批量表滞后 ~2 天，最新版在性能段常态无数据，误判成故障会天天误报。

**口径（周报）**

- 周报承接「主力版本」视角：新增放量段，按**会话量 top2**（非版本号）呈现两个主力版本的会话/设备/崩溃事件数，与日报的「最新 2 版」形成互补——日报看新版发得怎么样，周报看盘子里大头是什么。

**呈现**

- 日报卡片重构：由「崩溃表 + 性能表（列=iOS/Android）」改为「iOS 表 + Android 表（列=最新版 | 上一版 | 对比）」，崩溃与性能指标合并进同一张表（9 行），卡片更短且一屏内可比。
- 日报文档重构：改为「结论 → 双版本对照 → 明细 → 口径」四段式，口径说明统一收口到文末，不再逐段插注释。
- 周报卡片与周报文档重构：卡片按「变化摘要 + 主力版本放量」两段；文档补版本上下文。
- `reports/LEDGER.md` 台账重构：单张宽表拆为「活跃 issue 精简表（5 列）」+「历史归档折叠区」，长文本从表格移到条目正文，消除横向滚动。

**数据连续性**

- `state/metrics-history.jsonl` 改为**按版本存储**（`{day, versions:{ios:[…],android:[…]}, ios:{"1.5.4":{…}}}`），旧格式行（无 `versions` 键）在读取时**自动丢弃并打印提示**，实现「清空重建」而无需人工删文件；重建期间环比显示「无基准」。

## Capabilities

### New Capabilities

- `crash-perf-latest-2-versions`: 日报按最新 2 个版本全量过滤与分版本呈现的口径契约（版本解析、版本级过滤、版本无数据 vs 数据未同步、版本间对比指示器、按版本存储的环比基准），以及周报主力版本放量段

## Impact

**SQL**（`bin/sql/`）：新增 `latest-versions.sql`；`crash-issues` / `crash-rate` / `daily-crash-1d` / `daily-sessions-1d` / `daily-perf-1d` / `perf-traces` / `perf-screens` / `perf-network` 八个文件各加 `{{VERSIONS}}` 谓词（perf 系用顶层 `app_display_version`，crashlytics/sessions 系用 `application.display_version`，字段路径不同不可共用模板）；`sessions-by-version.sql` 保留全版本（放量明细仍需看全貌）；`README.md` 占位符约定加一行。

**脚本**：`bin/crash-daily.sh` 全量数据段与呈现段重构（版本解析、逐版本取数、卡片双表、文档四段、索引页、历史按版本存储）；`bin/crash-weekly.sh` 新增 bq 放量段与卡片/文档重构。`scripts/crash-report/` 双副本同步。

**文档**：`reports/LEDGER.md` 版式重构（内容不改写、只重排）；`bin/INSTALL.md` 配置项新增 `CRASH_REPORT_VERSION_COUNT` / `CRASH_REPORT_MIN_SESSIONS`。

**契约冲突**：`crash-perf-daily-monitoring` spec 断言「小样本提示粒度钉死平台级，MUST NOT 按版本细分会话数」——本次改为版本级，须在该 change 归档后以 MODIFIED delta 修订，或在本 change 的 spec 中显式声明取代关系（见 design.md）。

**风险**：查询数量由 ~30 增至 ~46（逐版本取数），单次运行耗时上升；最新版在性能段常态无数据（批量表滞后），卡片会出现整列「该版本无数据」——这是真实情况的如实呈现，非缺陷。
