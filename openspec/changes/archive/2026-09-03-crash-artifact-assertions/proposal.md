## Why

**仓库有查代码的（`check-scripts.sh` 九项）、有查函数的（`bin/test/fn-*.sh`），唯独没有查产物的。**
于是产物的正确性一直靠人临时想到什么就 grep 什么——想不到就漏。

2026-09-02 一天之内同一种失效连发三次，每次换个位置：

| 验的 | 漏的 |
|---|---|
| 链接**总数** > 0 | 每个平台都有吗 → Android 四段全是坏链接（F43，用户发现） |
| 卡片列宽没变 | 链接点得开吗 → 白发一张卡片（F42） |
| `__REPORT_URL__` 填上了 | 一共有几个占位符 → 日报卡片是另外三个，用户点到死链 |

根因不是粗心，是**验收对象错了**：每次问的都是「我改的那处生效了吗」——改动维度上的一个是非题；
于是**没改到的维度、以及有变体的维度（平台 / 占位符集 / 卡片元素类型）全部落空**（F44）。

⚠️ 本 change 是**追认**：实现已于 2026-09-02 落地并部署（`1acf234`），
09-03 首次在真实定时跑批中运行、4 通过 0 失败。补规格的原因是那几条决定
（挂在哪、失败时中止还是告警、判据形状）**后人查不到理由**，而它们都是有取舍的。

## What Changes

- 新增 `bin/test/assert-artifacts.sh`：对 `$STATE/publish/` 下的产物断言不变量，⛔ 与「本轮改了什么」无关。
- 挂进 L1 / L2 两条链路的**投递之前**：产物已齐、尚未发出，此时发现代价最小。
- ⚠️ **只告警不中止**：链接一类是增强项失效，数字本身没错，为它拦下整条投递不划算；⛔ 但必须显眼。
- ⛔ 调用放在 `if` 条件位——它失败时返回非零，裸调会触发 ERR trap 发假告警卡。

当前断言集：
- 每行**首列**的 id 单元格必须是链接；href 必须是 URL；app id 必须与所在段的平台一致
- 卡片表格单元格不得含链接（实测 CardKit 表格不渲染，写进去是字面 markdown 并撑宽）
- 卡片列名不得撞 CardKit 平台变体键（`ios`/`android`/`pc`/`harmony`）
- 占位符残留检查默认关闭（未投递产物本就带占位符），`CHECK_PLACEHOLDERS=1` 才查

## Non-goals

- ⛔ **不做成投递闸门**。产物断言失败不阻止投递——数字正确的报告晚发或不发，代价远大于少几个链接。
- ⛔ **不并入 `check-scripts.sh`**。那是**静态**代码检查，不依赖产物存在；且它是文档化的「九项」，
  加第十项会让既有约束的表述失真。
- ⛔ **不追求断言完备**。只收录「实际漏过、且能机械判定」的不变量；靠猜想出来的断言会带来假阳性，
  而假阳性会训练人忽略这个检查。
