## D1 · 通路：逐个 `crashlytics_get_issue`，⛔ 不回 `topIssues`

`topIssues` 结构上给不出这件事——关闭即从列表消失，"不在列表里"同时意味着
「已关闭」「已静音」「排不进 top-N」「窗口内无事件」四件事，**不可区分**。
R4 当初就是因此被误判的（实测 `2a800b33` / `26335e5d` 是 OPEN 但排不进 top-20）。

逐个 `get_issue` 没有这个歧义：⛔ **它对已关闭的 issue 照常返回 state**
（2026-09-22 实测 12/12，含 7 CLOSED / 1 MUTED / 4 OPEN）。

⚠️ 成本：每个未命中缓存的 id 一次 MCP 调用。L1 每轮本来就 spawn 一次 MCP server
同步事实层状态，**复用同一个进程**，不新开第二个。

## D2 · 三态 + 一个缺失态，⛔ 四者不得合并

| state | 渲染 |
| --- | --- |
| `OPEN` | `开启` |
| `CLOSED` | `✅已关闭` |
| `MUTED` | `🔕已静音` |
| 取不到 / 未同步 | `？未取到` |
| 其他非空值 | **原样透传** |

- ⛔ **OPEN 不得渲染成空**：空与「取不到」无法区分，正是缺数三态那条纪律禁的事。
- ⛔ **未知不得当成 OPEN**：会把「已关掉的问题」重新推给人跟进；也不得当成 CLOSED
  （R4 的原话：那会让 issue 凭空消失）。
- **其他值原样透传**：Firebase 日后加新状态时，宁可渲染出一个看不懂的词，
  也不要静默吞成已知三态之一。

## D3 · ⛔ 不给 extra id 建事实层文件

未命中缓存的 id 只在**本轮产物**里带上 state（`$CRASH_DIR/issue-states.json`），
⛔ **不往 `$STATE/issues/` 写桩记录**：

- 事实层的 `.source` 字段区分「只有聚合事实」与「有完整事件数组」，由创建者写死，
  桩记录会污染它（口径文档：「更新时不碰 `.source`」，实测踩过 7 条被覆盖）；
- `assert-fact-cache.sh` 的断言链建立在「记录由 L2 抓取路径创建」之上，
  桩记录会让断言对着半个记录打 ✅。

⇒ 事实层仍由 L2 独占写入，L1 只读它、外加一张**本轮内**的补充映射。

## D4 · 列命名：原「状态」列改叫「生命周期」

原列渲染的是 `life_tag()` → 🆕新增 / 🔁回归 / 长期，**与开关状态正交**。
在它旁边再加一列「开关」而不改名，等于把 F26「同名不同义」直接做进同一张表。

⚠️ 这是**列名变更**，两处渲染点（`issues_table` 的 markdown 与 `xml_issues`
的 DocxXML）必须同改——F35 那条：其中一处（markdown 预览）就是验收工具本身。
⚠️ `xml_csv_table` 的链接列规格 `1:8:<prefix>` 里的 **8 是完整 id 的列号**，
加一列后必须改成 9，否则链接指向「最新」列的内容（不会报错，会静默产出坏链接）。

## D5 · 降级：MCP 不可用时不阻塞

- 状态同步失败 → 沿用缓存里的既有 state（现有行为，不改）；
- 缓存里也没有 → 渲染 `？未取到`；
- ⛔ **不因为取不到状态而中止跑批**：它是标注列，不参与任何数字，
  为它中止会把次要降级升级成主要故障（与事实层那条同源）。
