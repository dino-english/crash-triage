## F1 ✅ 已解决（change `crash-alert-sample-fallback`，2026-08-22）

处置采用选项 B（小样本回退）。实测：`🔴 ANR 率 Android 1.5.3 0.71%` 现在会告警，且 1.5.4 的 `8.33%(3/36)` 误报同时消除。以下为原始记录。

### 原记录：ANR 超标但不会告警——design D6 的预测是错的

design D6 写的是「实测 0.743% / 0.794% 高于 0.47% 红线，首次纳入统计**必然触发红档告警**，上线前须预告」。

**2026-08-22 整跑实测：没有触发。**

| 版本 | 会话数 | ANR 率 | 是否告警 |
|---|---|---|---|
| Android **1.5.4**（最新） | **35** | 0.00% | 摘要行只看它 → 不告警 |
| Android 1.5.3（主力） | 6331 | **0.76%** 🔴 | 只着色，不告警 |
| Android 1.5.1 | 1778 | **0.96%** 🔴 | 只着色，不告警 |

原因：既定口径「**告警只由最新版触发**」（上一版与主力补充列只着色不告警——既定事实拦不了发版）。
而 1.5.4 在我测量与本次跑批之间刚发布，只有 35 个会话、0 次 ANR。

**后果**：本 change 的核心目的是让 ANR 从不可见变为可见，结果**它在摘要行里依然不可见**。
文档表格里能看到 0.76% 的红色，但卡片摘要行——多数人只看这一行——是空的。

**这不是本 change 引入的缺陷，是既有告警口径的固有局限**（同样适用于崩溃率：1.5.4 的 5.71% 是 2/35，
统计上毫无意义，却因为是最新版而触发了红档；而真正有 6331 会话的 1.5.3 只有 0.36%）。
**新版刚放量的窗口里，告警既会误报也会漏报。** ANR 的加入只是让这个问题第一次有了具体代价。

### 三个可选处置（需人工决定，本 change 不擅自改口径）

- **A. 维持现状**：文档可见即可，摘要行漏报接受。成本 0。
- **B. 小样本回退（推荐）**：最新版会话数低于 `SAMPLE_SESSION_MIN` 时，告警判定回退到**会话量最大的版本**。
  既解决漏报（主力版超标能报出来），也解决误报（1.5.4 的 2/35 不再触发红档）。
  ⚠️ 但这改变了「告警只由最新版触发」这条既定口径，属于独立 change。
- **C. 仅对 ANR 特例**：ANR 告警看主力版，其余指标不变。口径不一致，不推荐。

## F4 ⛔ 台账同步无法在开发机验证（task 3b.5 阻塞）

台账同步只在真实投递时执行，而 `deliver.sh` 的自测闸门在投 `ou_`（开发机身份）时**刻意跳过台账同步**——
两台机器的 `docs.json` 指向**同一份**台账文档，绕过闸门会把测试数据写进群里那份正式台账。

**需要生产机做一次，且需先人工准备**：在台账飞书文档中加入「NON_FATAL 现状表」标题与一张占位表格。
`sync_ledger()` 定位不到该标题时**只警告不中止**（FATAL 表照常同步），所以即便忘了准备也不会破坏现有台账。

已在开发机验证到的部分：
- `render-ledger.sh` 三段输出正确（FATAL 表 / 时间线 / NON_FATAL 表）
- 本地台账源 `LEDGER.md` 的 `<!-- LEDGER:NONFATAL:BEGIN/END -->` 锚点替换正确
- `manifest.json` 携带 `ledger_sync.nonfatal_file`
- 未验证的只有飞书侧的 `block_replace` 那一步

### F4 后续：闸门已收窄，台账同步现在**可以**在开发机验证

原判断「本机无法验证」不完全对——**deliver.sh 是同一份脚本，只是按 `CHAT_ID` 前缀分叉**
（`oc_` → `IS_PROD=1`），而闸门 `[ "$IS_PROD" != "1" ]` 在解析 `LEDGER_DOC_ID` **之前**就跳过了，
所以连「指向另一份测试文档」这条路都被堵死。

闸门的理由是「它是群里那份固定文档」——**这个理由只在目标就是那份文档时成立**。
闸门比它的理由宽。已收窄为：

| 场景 | 结果 |
|---|---|
| 生产机（`oc_`） | 放行 |
| 开发机 · 未指定 `CRASH_REPORT_LEDGER_DOC_ID` | 拒绝（默认行为不变） |
| 开发机 · 指向 `docs.json` 里那份生产台账 | **拒绝**（关键：显式指也不行） |
| 开发机 · 指向另一份文档 | 放行 |

四种情形已逐一验证。这比原闸门**更窄**：以前是「非群一律不同步」，现在是「非群且目标是生产台账才不同步」。

验证方式：
```bash
# 另建一份测试文档，把 id 传进去
CRASH_REPORT_LEDGER_DOC_ID=<测试文档 id> bash bin/deliver.sh <weekly manifest>
```
