## Context

动机与实测见 [proposal.md](proposal.md)。这里只记约束。

`$STATE/backup/` 目前**没有任何写入者**（`fetch-snapshot.sh:436` 的 `corrupt-issues-*` 是隔离区，
语义是「这份数据坏了，挪开别用」，不是「留一份好的」）。目录里的东西全是人手放的。
⚠️ `docs/CLAUDE-部署与运维.md` 对该目录的描述「台账等不可再生内容的**手工**备份，无写入者」
是**准确的**——它如实记录了现状，问题不在文档，在于没人把它变成机制。

## Goals / Non-Goals

**Goals：**
- 人工结论在误覆写 / 误删 / 损坏后可原样恢复
- 「备份有效」这件事可被产物证伪，⛔ 不靠「代码里写了备份」来推断

**Non-Goals：** 见 proposal 的 Non-goals（异地、版本历史、自动清理、推广到其他文件）

## Decisions

### D1：内容变化时才落副本，⛔ 不是每轮都落

**决定**：与最近一份副本 `cmp` 不同才写新副本。

**为什么**：结论是人工低频更新的，每周落一份相同内容的副本，一年后是 52 份一模一样的文件——
⚠️ 那不只是浪费，它会让「哪一份是变更点」这个唯一有用的信息被淹没。回滚时人要的是
「上次改动之前长什么样」，不是「上周一长什么样」。

### D2：成功判据是 `cmp` 一致，⛔ 不是「文件存在」

**决定**：写完立刻 `cmp` 副本与现役文件，不一致即告警。

**为什么**：这条正是本 change 存在的理由。`crash-ledger-disposition-store` 的 task 1.3
用「文档里出现该路径」当判据，于是写一句话就绿了。⛔ 判据必须能被**产物**证伪：
副本在盘上且内容逐字节相同，这个断言写文档是满足不了的。
⚠️ 同 F57「投递成功 ≠ 渲染正确 ≠ 内容写进去了」——那条讲写操作，这条讲备份，同一个病。

### D3：备份失败告警但不中止跑批

**决定**：失败打 ⚠️ 并继续，⛔ 不触发 ERR trap、不改退出码。

**为什么**：备份是保护措施。让它能拦下整条周报，等于为了防数据丢失而制造一次投递失败——
⚠️ 而且它会走 ERR trap 发告警卡（本仓库「新增检查不得走触发 ERR trap 的路径」）。
⛔ 代价要说清：备份静默失效时只有日志里一行 ⚠️。这是刻意取舍，不是遗漏。

### D4：放在 L2 收尾，⛔ 不碰 L1

**决定**：写在 `crash-weekly.sh` 的收尾段，在完成哨兵 `RUN_COMPLETED=1` 之前。

**为什么**：L2 是唯一读这个文件的链路，备份跟着它走，⛔ 不为「更勤快」去破 L1 的边界
（`crash-perf-daily-weekly-report` 的职责边界刚在上一个 change 里被收紧过）。
⚠️ 代价：备份频率 = 周。人在周报后更新结论，下一次落盘要等一周。
**这个窗口由「应急人工备份」兜**——`$STATE/backup/` 允许人随时手工 `cp`，文档会写明。

## Risks / Trade-offs

- **周级频率下，一周内的两次人工编辑只留最后一次的前值** → 接受。要更细粒度就得上版本控制，
  而那是 Non-goal（生产机推不了 git）。
- **`$STATE` 整个丢失时副本一起没** → 本 change 解不了，proposal 已写明；异地靠人工 scp。
- ⚠️ **备份目录只增不清** → 按 D1 只在变化时落，量级是「人工编辑次数」，可忽略。

## Migration Plan

1. `crash-weekly.sh` 收尾加备份 + `cmp` 断言
2. 夹具补断言（首次落盘 / 内容未变不重复落 / 变化后落新副本 / 失败不改退出码）
3. `check-scripts.sh` 十项 + `NO_DELIVER` 整跑
4. 部署，下一轮生产跑批后确认 `$STATE/backup/dispositions/` 里有与现役一致的副本

**回滚**：删掉那段即可，已落的副本保留不删。
