## Context

动机与证据链见 [proposal.md](proposal.md) 的 Why。这里只记实现约束。

**两条写入路径，成本结构完全不同**：

| 路径 | 数据来源 | `hit` 分支省下什么 |
|---|---|---|
| `fetch-snapshot-bq.sh`（确定性 shell） | `$SNAP` —— 已经是 bq 查询的结果 | **一次 `jq` + `mv`，仅此而已** |
| `fetch-snapshot.sh`（模型执行 prompt） | MCP `topIssues` + `crashlytics_list_events` | **一次昂贵的 MCP 调用**（prompt 原文：「这是本次判定的核心目的：0 次额外 MCP 调用」） |

这个不对称是整个设计的支点：同一个 `if/else` 在一条路径上是真优化，在另一条上是纯粹的有害。

**数据现状**（2026-08-22 实测）：18 个文件，12 条模型路径 + 6 条 bq 路径。bq 记录各 4K，模型记录 8K–404K（带完整 `events` 数组）。量级小到迁移与重写成本可忽略。

## Goals / Non-Goals

**Goals:**

- 让「最近一次发生」与「最近同步」在任何观测轮次后都反映真实观测时刻。
- 让存下来的计数可被解释（附带窗口口径）。
- 保住模型路径省 MCP 调用的收益——**这个不能丢**。

**Non-Goals**（proposal 已列，此处只加设计级边界）：

- **不改 `events` 累积数组的合并语义**。它由 spec 的「既有事件记录不被改写」约束，本 change 不碰。
- **不为 `window_days` 做历史回填**。现存 18 个文件缺该键，读取端按「未知窗口」处理即可；下一轮跑批自然补上。

## Decisions

### D1：拆开「抓取判定」与「记录判定」

现行实现把两件事挤在一个 `if/else` 里：

```
if 强制 或 文件不存在:  写新文件
elif 本次 > 上次:        更新计数与时间戳     ← 记录
else:                    什么都不做           ← 既跳过抓取，也跳过记录
```

改为两段顺序执行：

```
① 抓取判定 → new | append | skip     （只决定要不要抓事件明细）
② 记录更新 → 无条件执行               （观测字段一律刷新）
```

**否决「bq 路径直接删掉命中判定」**：两条路径的判定逻辑若不一致，`fetch-snapshot.sh` 的 prompt 与 shell 实现就再也无法互相印证——那份重复本就是已知缺口（`crash-perf-functional-core` design D10），让它进一步分叉会让将来的统一更难。**保持同一套判定语义，只是 bq 路径上「抓取」退化为空操作。**

**否决「把观测字段更新塞进现有 else 分支」**：那只是把三分支改成四分支，两个判定仍然纠缠。真正的问题是它们本就该是两个独立决策。

### D2：`latest_event` 取 max，不直接覆盖

窗口内的 `MAX(event_timestamp)` **同样非单调**——这是比计数更隐蔽的一处。当窗口内最新的那条事件滑出窗口后，剩余事件的 MAX 会比上一轮更早。

若 D1 只做「无条件覆盖观测字段」而不加 max，就会把一个 bug（冻结）换成另一个 bug（倒退）——而**倒退更糟**：冻结至少还是个真实发生过的时刻，倒退会让台账显示一个比真实「最近一次发生」更早的时间，读者据此判断「这个崩溃很久没出现了」，正好相反。

**否决「latest_event 也无条件覆盖」**：见上。
**否决「改用不带窗口的查询取 latest_event」**：那要额外一次全表扫描，成本与收益不成比例；max 是零成本的等价保证。

### D3：`window_days` 随记录落盘，不做全局约定

计数是窗口内的取值，窗口长度是解释它的必要前提。窗口长度由 `CRASH_REPORT_CRASH_DAYS` 等环境变量决定，**可以在两轮之间变化**——把它写死在文档里而不是记录里，跨轮比较就会静默出错。

**否决「假设窗口恒定、不记录」**：正是这类隐式假设造成了本 change 要修的问题。同一个错误不犯第二次。

### D4：`CACHED_HIT` 的语义与措辞同步

改动后 `hit` 的含义从「跳过写入」变为「跳过抓取」。日志行 `事实层缓存: 新增 N · 更新 N · 命中跳过 N` 会产生歧义——bq 路径上每条记录都被写入，却仍报「命中跳过」。

措辞改为区分两件事：`抓取 新建 N · 增量 N · 跳过 N` 与 `记录 更新 N`。**运维日志的可读性是这套系统反复吃亏的地方**（`hermes cron run` 的假 `failed`、`table_exists` 的静默降级），不在这里再造一个。

### D5：消除 prompt 重复，而不是检测它

`fetch-snapshot.sh` 的第 ③ 段在文件里出现**两份**（约 80-95 行与 124-137 行，light / full 两种模式）。prompt 是自然语言：没有语法检查、没有 lint、**改漏一份不会报错**，只会让模型在某个模式下按旧策略执行。

**选择：把重复段提取为单一 shell 变量，两处 prompt 都插值引用。**

```bash
FACT_CACHE_POLICY='③ 事实层缓存 …（策略全文）…'
# light 模式 heredoc 里：${FACT_CACHE_POLICY}
# full  模式 heredoc 里：${FACT_CACHE_POLICY}
```

重复物理消失，就不需要任何机制去检测它。两种模式若确有措辞差异，差异部分留在各自 heredoc 里，**共享的策略描述只有一份**。

**否决「加 lint 检查两段一致」**：需要语义比较，做不到；退化成「加版本号锚点注释、lint 校验版本号一致」的话，改了文本忘了改版本号仍然漏——**用一个同样会被忘记的东西去防止遗忘**。

**否决「靠 hook 在编辑后检查」**：只在经由该编辑器改动时生效，直接 `vim` 改就绕过了。可以作为开发期的快速反馈，**不能作为唯一防线**。

### D6：prompt 的唯一有效检查是对其产物的断言

D5 消除的是「改漏一份」。但 prompt 还有一类失败它防不住：**两份都改对了，模型没照做**。自然语言指令没有执行保证，措辞一致 ≠ 行为一致。

因此模型路径的验收 MUST 落在**产物断言**上，而非 prompt 文本：跑完一轮后校验 `$STATE/issues/*.json` —— 本轮观测到的 issue，其 `last_synced` 是否为本轮时刻、`latest_event` 是否未倒退、`window_days` 是否写入。

**这是 prompt 类代码唯一可靠的测试形式**，与确定性 shell 的单元测试是同一件事的两种形态：断言的对象从函数返回值换成落盘产物。

`crash-perf-functional-core` 的三层等价性 diff 已经建立了「按清单收集产物并比对」的机制，本 change 的产物断言复用同一套思路（不复用同一份代码——那个 change 比的是「与基线一致」，这里断的是「符合规格」）。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| **只改覆盖不加 max** → 冻结变倒退，比原问题更糟 | D2 是必做项，不是可选优化；tasks 中与 D1 同一步完成，不拆开 |
| **prompt 两份改漏一份** → 模型在某模式下按旧策略执行，无任何报错 | D5：提取为单一变量插值，重复物理消失——不检测重复，消除重复 |
| **两份都改对了但模型没照做**（自然语言无执行保证） | D6：验收落在产物断言而非 prompt 文本——跑完校验 `issues/*.json` 的 `last_synced` / `latest_event` / `window_days` |
| **每轮重写全部命中文件** → I/O 增加 | 当前 18 个文件、最大 404K，量级可忽略。若将来 issue 数量级上升，再考虑「仅当观测值有变化时写入」——但那要小心别退回成同一个 bug |
| **与 `crash-perf-functional-core` 的用例冲突** | 那个 change 的用例钉住的是**当前行为**并标注「已知缺陷」。本 change 落地时必须同步改写该用例的期望值——列为 tasks 的显式一项，不靠记性 |
| **`window_days` 缺失的历史记录被误读** | 读取端按「未知窗口」处理，不假设默认值；下一轮跑批自然补上 |

**接受的取舍**：本 change 消除了 prompt **内部**的两份重复（D5），但不解决「同一套策略在 prompt 与 shell 里各写一份」这个跨执行模型的重复。彻底的解法是把事实层维护移出 prompt，那需要模型路径也改用确定性抓取——超出本 change。

## Migration Plan

无迁移。现存 18 个文件缺 `window_days`，下一轮跑批补上；`latest_event` 取 max 保证不会因本次改动倒退。

**回滚**：`git revert`。回滚后已写入的 `window_days` 键成为无人读取的冗余字段，无害。
