# 实施中发现

## F1 `verdict_line` 按箭头判好坏，对非 lower_better 指标必然判反

结论行（「⚠️ 变差 … ✅ 变好 …」）原先按**箭头方向**分类：`↑` 归变差、`↓` 归变好。
这等价于假设**所有指标都越小越好**。

crash-free 是 `higher_better`，实测被判反：

```
Android 1.5.4 vs 1.5.3：✅ 变好 Crash-free 会话 7d -5.37pp ↓
```

crash-free 从 99.66% 掉到 94.29%，**是变差**。表格单元格本身是红的（`delta_cell` 判定正确），
只有结论行判反——因为它在匹配前把颜色标签 `sed` 掉了，只剩箭头可看。

**顺带修掉一个既有 bug**：`会话数` 是 `neutral` 指标（`delta_cell` 刻意不给它上色），
但箭头照出，于是「会话数 1d -1179 ↓」也被归进「✅ 变好」——放量掉一千多个会话说成变好是错的。

**修法**：改按**颜色**分类（红=变差、绿=变好、无色=不判）。`delta_cell` 本就把
「箭头跟数值方向、颜色跟好坏」分开编码了，结论行只是丢掉了后者。

⚠️ **这改变了既有行为**：`会话数` 从此不再出现在结论行的任何一栏。这是修正而非回归——
它是 neutral 指标，本就不该被判好坏——但属于本 change 范围外的顺带修复，需知悉。
