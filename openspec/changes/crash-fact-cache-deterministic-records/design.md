## Context

动机与实测证据见 [proposal.md](proposal.md)。这里只记实现约束。

**为什么观测字段可以脱离模型**：模型路径的 `snapshot.json` 结构里每个 issue 已经带
`events` / `users`（`fetch-snapshot.sh` prompt ① 段规定的结构）。观测字段要的就是这两个数
加上窗口天数与本轮时刻——**没有一项需要额外的 MCP 调用**。模型真正省下的是
`crashlytics_list_events`，那属于「判定一」，本 change 不碰。

## Decisions

### D1 · 观测字段的唯一写入方是确定性 shell

模型不再被要求写观测字段，prompt 的「判定二」整段删除。回写点放在
`fetch-snapshot.sh` 的重试循环**之后**、落盘校验（隔离非法 JSON）**之前**。

⚠️ 顺序不能反：先隔离再回写，会对刚被 `mv` 走的文件写出一个只有观测字段的残缺文件；
先回写再隔离，坏文件照常被隔离，下一轮全量重抓自动补回——与现有语义一致。

### D2 · 合并逻辑抽成 `bin/lib/factcache.sh`，两条路径各自 source

⛔ **不放 `bin/lib/core/`**：该函数要落盘到 `$STATE/issues/`，第 3 项依赖方向 lint 会拦下
（`grep` 命中 `$STATE`）。放 `bin/lib/`，**路径一律走参数**，函数体内不出现 `$STATE`。

⚠️ **函数不跨进程**：`fetch-snapshot-bq.sh` 与 `fetch-snapshot.sh` 是两个独立子进程，
各自 `source` 一次。这是本仓库既有约定，不是遗漏。

### D3 · `last_synced` 的契约写死为真 UTC

值 MUST 由 `date -u +%Y-%m-%dT%H:%M:%SZ` 产生。**一个写入方、一种格式**——
这是「三种口径并存」在结构上不可能再发生的唯一保证。

⛔ 不接受「在 prompt 里把格式写得更清楚」这类修法：09-07 的 prompt 已经写着
「`last_synced`（本轮 ISO8601 时刻）」，模型照样写成本地时间标 Z。
**措辞一致 ≠ 行为一致**（同一份 design 的原话）。

### D4 · 断言改判「时刻」，不判「日期前缀」

现行 `case "$ls_" in "$TODAY"*)` 的粒度是天，且基准是 UTC 日期。改为解析出时刻、
与本轮开始时刻比差值，容差取一轮跑批的最长时长（建议 30 分钟，L2 实测 8 分钟）。

⚠️ **改完必须做双向测试**（本仓库对新增检查的硬要求）：
真 UTC 且本轮 → ✅；真 UTC 但上一轮 → ❌；本地时间标 Z → ❌（**现在它在 L1 场景会误过**）。
夹具直接跑 `assert-fact-cache.sh`，`CRASH_REPORT_STATE_DIR` 指向临时目录即可，不需要跑批。

### D5 · 内容覆盖率只输出，不 gating

新增一行「声称事件 N / 实存 M / 覆盖率」。⛔ **本 change 不给它设阈值**：
当前基线是 55 vs 6，任何阈值现在都会全红，把一条要长期看的观测指标一次性变成噪音
（F30 登记过这类「新加的检查自己成了告警噪音源」）。先让它可见，攒够几轮再定阈值。

### D6 · 本 change 必须先于「修模型抓取内容」落地

L2 顺序是 shell 写 → 模型写 → 断言，模型写在后可覆盖正确时刻。
**只要模型还在写 `last_synced`，修好它的写入能力就会立刻炸出一条假告警**（F45 实测）。
本 change 把该字段从模型手里拿走后，这条依赖自动解除。

## Risks / Trade-offs

- **每轮重写全部命中 issue 的 JSON**：当前 25 个文件、单文件 4K–404K，`jq` + `mv` 的成本可忽略。
- **回写失败的可见性**：`jq` 失败必须走现有落盘校验路径并计入隔离计数，⛔ 不得 `|| true` 吞掉。
- **模型仍可能写坏 `events`**：本 change 不解决，只让它在覆盖率行上可见（Non-goal，另起 change）。
