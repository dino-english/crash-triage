# crash-perf-issue-fact-cache Specification

## Purpose

定义崩溃事件事实层的落盘、命中判定与增量抓取语义。崩溃事件是不可变的历史事实，一次抓取应永久可用，避免每轮重复抓取同一批历史事件。

## Requirements

### Requirement: 事实层按 issue 落盘并永久保留

每个 issue 的完整事件详情 MUST 以该 issue 的完整标识落盘保存，且不参与任何按时间的自动清理。

#### Scenario: 首次抓取某 issue

- **WHEN** 某 issue 的事实层记录不存在
- **THEN** 抓取其事件详情并落盘
- **AND** 落盘内容包含分析所需字段：堆栈帧、设备型号、系统版本、可用内存、进程状态、崩溃前屏幕、操作轨迹、构建标识

#### Scenario: 跑批产物清理执行

- **WHEN** 按期清理过期跑批产物
- **THEN** 事实层记录不被删除

### Requirement: 已有事实优先读本地

跑批时 MUST 先判定本地事实层是否已覆盖所需事件，命中则不重复抓取。

该判定 MUST 仅决定**是否发起事件明细抓取**，MUST NOT 同时决定是否更新观测字段——两者是不同的判断，观测字段的更新要求见「观测字段每轮无条件更新」。

判定所依据的线上事件计数 MAY 是某个时间窗口内的取值，因而**不保证单调递增**：窗口滑动会让老事件出窗，计数随之下降。实现 MUST NOT 假设该计数单调。

#### Scenario: 事实层已完整覆盖

- **WHEN** 某 issue 的本地事件数与线上事件数一致
- **THEN** 直接读取本地事实层
- **AND** 不发起该 issue 的事件详情抓取

#### Scenario: 线上有新增事件

- **WHEN** 某 issue 的线上事件数大于本地已存事件数
- **THEN** 只抓取新增部分并合并入本地事实层
- **AND** 既有事件记录不被改写

#### Scenario: 线上计数低于本地已存

- **WHEN** 某 issue 的线上事件数小于本地已存事件数（老事件滑出统计窗口所致）
- **THEN** 不发起事件详情抓取——计数下降意味着没有新事件
- **AND** 该 issue 的观测字段仍按「观测字段每轮无条件更新」被刷新
- **AND** 本地已有的累积事件记录不被删除或改写

#### Scenario: issue 已关闭且计数未变

- **WHEN** 某 issue 在线上已关闭且事件数与本地一致
- **THEN** 完全跳过该 issue 的抓取

### Requirement: 支持强制重抓

MUST 提供显式开关，在事实层疑似损坏或口径变更时打掉本地缓存重新抓取。

#### Scenario: 开启强制重抓

- **WHEN** 强制重抓开关被启用
- **THEN** 忽略本地事实层，对全部 issue 重新抓取
- **AND** 重抓结果覆盖本地记录

#### Scenario: 未开启强制重抓

- **WHEN** 强制重抓开关未启用
- **THEN** 按命中判定决定是否抓取

### Requirement: 事实层缺失不阻断分析降级

事实层抓取失败时， MUST 以已有本地内容继续，而非整段失败。

#### Scenario: 部分 issue 抓取失败

- **WHEN** 某些 issue 的事件详情抓取失败
- **AND** 另一些已有本地事实
- **THEN** 分析基于可用事实继续
- **AND** 报告显式标明哪些 issue 的事实不完整

#### Scenario: 区分「查过没有」与「未查」

- **WHEN** 某项事实经查证确实不存在
- **THEN** 记录为已查证的空值
- **AND** 不与「未查」混同呈现

### Requirement: 观测字段每轮无条件更新

事实层记录中反映「本轮观测到什么」的字段——最近一次事件时刻、最近同步时刻、事件计数、受影响用户数——MUST 在每一轮观测到该 issue 时更新，**无论抓取判定的结果是命中还是未命中**。

理由：这些字段记录的是观测行为本身，不是抓取产物。跳过它们不节省任何抓取成本，只会让「最近一次发生」与「最近同步」停留在历史某一刻，把**正在衰减的 issue 呈现为数据停更**——好消息被读成故障。

#### Scenario: 抓取被跳过但观测字段仍更新

- **WHEN** 某 issue 因计数未变或计数下降而跳过事件详情抓取
- **THEN** 其最近同步时刻被更新为本轮时刻
- **AND** 其事件计数与受影响用户数被更新为本轮观测值

#### Scenario: 衰减中的 issue 不被误判为停更

- **WHEN** 某 issue 连续多轮计数下降（修复生效、崩溃减少）
- **THEN** 每一轮的最近同步时刻都反映真实的观测时刻
- **AND** 台账与报告中该 issue 不呈现为「数据未同步」

### Requirement: 最近一次事件时刻单调不倒退

事实层记录的「最近一次事件时刻」MUST 单调不倒退：每轮更新时取「已存值」与「本轮观测值」中较晚的一个。

理由：线上查询返回的是窗口内的最大事件时刻。当窗口内最新的那条事件滑出窗口后，剩余事件的最大时刻会**比上一轮更早**。直接覆盖会让该字段倒退，使台账的「最近一次发生」显示为比实际更早的时刻。

#### Scenario: 窗口滑动导致观测值变早

- **WHEN** 本轮观测到的最近事件时刻早于本地已存值
- **THEN** 保留本地已存值不变
- **AND** 其余观测字段照常更新

#### Scenario: 确实发生了更晚的事件

- **WHEN** 本轮观测到的最近事件时刻晚于本地已存值
- **THEN** 更新为本轮观测值

### Requirement: 窗口口径随计数一并记录

事实层记录 MUST 一并保存该计数所依据的时间窗口长度。

理由：「7 天内 3 次」与「30 天内 3 次」是不同的事实。不记录窗口，存下来的数字无法被解释，跨轮比较也不成立——窗口长度变化时，计数变化不代表崩溃量变化。

#### Scenario: 读取历史记录

- **WHEN** 读取某 issue 的事实层记录
- **THEN** 可从记录本身判定其计数对应的窗口长度

#### Scenario: 窗口长度在两轮之间发生变化

- **WHEN** 两轮跑批使用了不同的窗口长度
- **THEN** 记录反映本轮实际使用的窗口长度

### Requirement: 事实层更新必须被验证而非被信任

每轮跑批 MUST 对**落盘的事实层产物**断言「观测字段每轮无条件更新」确已成立，
MUST NOT 以执行者的自陈（模型回复、日志文本）作为该要求成立的判据。

理由：执行该要求的是模型按自然语言策略行事，没有语法检查也没有退出码。
2026-09-04 实测该模型会把任意错误归因成权限拒绝（收到 `EROFS` 也回报 `DENIED:Write`），
其自陈与实际行为无对应关系。同期另一轮它把「线上计数大于本地」误判为命中并跳过。
两轮都以成功收场，因为成功判据只看主产物是否写出——**两端判据不一致即静默降级**。

#### Scenario: 事实层未按要求刷新

- **WHEN** 本轮快照中任一 issue 的事实层记录的最近同步时刻不是本轮
- **THEN** MUST 在跑批日志中列出全部未刷新的 issue 及其停滞时刻
- **AND** MUST 在卡片可见处告警，说明**受影响的是台账的事件明细、而非本轮任何数字**
- **AND** MUST 一并给出补救办法（强制重抓后重跑）
- **AND** MUST NOT 使跑批失败——事实层不参与报告任何数字，为它中止跑批会把次要降级升级成主要故障

#### Scenario: 事实层已按要求刷新

- **WHEN** 本轮快照中全部 issue 的最近同步时刻均为本轮
- **THEN** MUST NOT 产生任何告警或注记

#### Scenario: 上游取数整体失败

- **WHEN** 本轮未能产出快照（上游抓取失败）
- **THEN** MUST NOT 追加事实层告警——该路径已有自己的告警，重复只会稀释

#### Scenario: 断言调用自身的失败语义

- **WHEN** 断言以非零退出码表示未通过
- **THEN** 调用 MUST 位于条件上下文中，避免在 `set -e` 与 ERR trap 下产生假故障告警
- **AND** MUST NOT 以命令替换包裹断言调用——`errtrace` 会把 ERR trap 传入子 shell，外层的 `||` 兜不住

#### Scenario: 新增或修改该断言的接入

- **WHEN** 改动断言的接入方式
- **THEN** MUST 在生产 shell 设置（`set -euo pipefail` + `errtrace` + ERR trap）下红绿两侧都验证
- **AND** MUST 验证告警路径本身不触发 ERR trap

#### Scenario: 断言无法执行时不得报成判定失败

- **WHEN** 断言因自身前置条件不满足而无法执行（快照缺失、快照中没有 issue）
- **THEN** MUST 与「判定为未刷新」区分呈现，说明这是**没查成**而非已确认陈旧
- **AND** MUST 照抄断言自身给出的原因，⛔ MUST NOT 猜测
- **AND** ⛔ MUST NOT 从「无法执行」的输出里推算出任何 issue 计数——
  2026-09-05 实测：把护栏输出当成一条 issue 失败记录去数，会在卡片上发出
  「N 个 issue 的观测字段不是本轮」这样的假告警，而那 N 个 issue 并不存在
