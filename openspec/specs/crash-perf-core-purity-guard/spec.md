# crash-perf-core-purity-guard Specification

## Purpose
约束崩溃 & 性能流水线的纯函数核心层：规定哪些函数必须无副作用、共享函数只能有一处定义、依赖方向只能由外向内，并由提交前自检脚本以退出码强制这些约束。目的是让阈值判定、格式化、版本挑选这类「算错了不会报错、只会安静输出错数字」的逻辑变得可断言、可回归。

## Requirements

### Requirement: 纯函数核心层无副作用

核心层函数 MUST 是纯函数：给定相同入参产出相同结果。具体地，MUST NOT 读写文件、MUST NOT 发起网络或数据查询、MUST NOT 读取当前时刻、MUST NOT 引用脚本全局变量。所有输入 MUST 经由位置参数传入，所有输出 MUST 经由 stdout 返回。

文本处理子进程（算术、格式化、排序、时间戳格式化）不违反本约束——它们在给定入参下是确定的。判定标准是**是否读取了参数之外的状态**，而非是否 fork 了进程：把一个 epoch 数值格式化成日期字符串是纯的，取「现在几点」不是。

依赖当前时刻的函数 MUST 改为接收基准时刻作为参数，由调用方在流水线启动时取一次并传入。

核心层 MUST NOT 依赖任何全局变量，因而其加载顺序 MUST 是任意的——加载核心层不得要求先完成任何配置或路径解析。

#### Scenario: 核心层函数可脱离流水线独立调用

- **WHEN** 在一个未设置任何流水线环境变量、未解析运行目录与状态目录的 shell 中加载核心层
- **THEN** 加载成功且不产生任何输出或副作用
- **AND** 任一核心层函数可直接以位置参数调用并返回正确结果

#### Scenario: 核心层被要求读取外部状态

- **WHEN** 某个核心层函数需要文件内容或查询结果才能得出结果
- **THEN** 该函数不属于核心层，其外部输入 MUST 由调用方取得后作为参数传入

#### Scenario: 时间窗口计算

- **WHEN** 计算取数区间起点、或判定数据源停更天数
- **THEN** 基准时刻由调用方作为参数传入，函数自身不读取当前时刻
- **AND** 同一组入参在任何时刻调用都得到相同结果，可被断言用例固定

### Requirement: 依赖方向自检

提交前自检 MUST 检测核心层是否出现外层依赖，包括数据查询命令、投递命令、模型调用命令、网络请求命令，以及对运行目录 / 状态目录变量的引用。检测到任一违规时自检 MUST 以非零码退出，并指出违规的文件、行号与命中的内容。

#### Scenario: 核心层引入取数调用

- **WHEN** 有人在核心层文件中写入 BigQuery 查询或投递命令
- **THEN** 自检失败并输出该文件与行号
- **AND** 自检退出码非零

#### Scenario: 核心层保持纯净

- **WHEN** 核心层文件不含任何外层依赖
- **THEN** 依赖方向检查通过，不影响自检整体退出码

### Requirement: 共享函数单一定义

同名函数出现在两个及以上**生产**脚本中即判定为违规，由提交前自检以退出码强制。
豁免项 MUST 以数据形式集中列出，每项附一行理由。

⛔ 本项 MUST NOT 比对测试夹具（`bin/test/`）。理由是结构性的：本项的判据是
「共享函数应收口到公共层」，而夹具中的函数**本来就不该被收口**——它们是桩与局部助手。
把夹具一并比对的结果是本项长期常红，而**常红等于没有**：2026-09-05 一天三次部署，
每次都看见同一批 ❌，新旧无从分辨。

⚠️ 代价 MUST 被记录：夹具**照抄**生产函数（而非从生产脚本抽取）这种情况本项不再报出。
但本项只比对函数名、不比对函数体，本来也分辨不了「桩」与「照抄」——那属于测试质量，
归函数级测试夹具的抽取约定负责，不该由重复定义检测兼职。

⚠️ 自检的其余各项 MUST 仍然递归覆盖 `bin/test/`（语法、多字节变量 lint、先用后定等）。

#### Scenario: 同名函数被复制到第二个脚本

- **WHEN** 同一函数名在两个入口脚本中各有一处定义
- **THEN** 自检失败并列出该函数名与出现的全部文件

#### Scenario: 两条链路共用同一份实现

- **WHEN** 日报链路与周报链路都需要同一个错误处理函数，且行为仅在告警来源标识上不同
- **THEN** 该函数只定义一次，来源标识由调用方传入或预设
- **AND** 修改该函数一次即对两条链路同时生效

#### Scenario: 两个生产脚本定义同名函数

- **WHEN** 同一函数名出现在两个及以上生产脚本中且不在豁免清单
- **THEN** 自检 MUST 失败并列出涉及的文件

#### Scenario: 生产脚本与公共层定义同名函数

- **WHEN** 某函数同时定义在生产脚本与公共层
- **THEN** 自检 MUST 失败——这正是应当收口的场景

#### Scenario: 夹具内部或夹具对生产函数打桩

- **WHEN** 重名只发生在测试夹具之间，或夹具为生产函数提供同名的桩
- **THEN** 本项 MUST NOT 报出

### Requirement: 纯函数断言覆盖

核心层每个对外可调用的函数 MUST 有断言用例覆盖，且 MUST 包含既有实现中已知的边界情形：空字符串输入、除数为零、无法计算的取值、负向增量、以及只有单一版本可比时的退化情形。

提交前自检 MUST 运行全部断言用例；任一用例失败时自检 MUST 以非零码退出。

#### Scenario: 纯函数被改坏

- **WHEN** 某个阈值判定或格式化函数的行为被错误修改
- **THEN** 对应断言用例失败
- **AND** 自检以非零码退出，改动无法在自检通过的前提下提交

#### Scenario: 除数为零

- **WHEN** 崩溃率计算的分母（会话数）为零或为空
- **THEN** 断言用例验证其返回「无法计算」的既有语义，而非返回零

#### Scenario: 新增核心层函数未配用例

- **WHEN** 核心层新增一个对外可调用的函数但没有对应断言用例
- **THEN** 自检报告该函数缺少覆盖并以非零码退出

### Requirement: 可选检查工具缺失时降级而不失败

自检所依赖的第三方工具（静态检查器、测试运行器）MUST 是可选依赖。工具未安装时自检 MUST 跳过该项、打印一行明确提示，并且 MUST NOT 因此失败——生产机的装机与更新流程不得因缺少开发期工具而中断。

工具已安装时，其报告的问题 MUST 计入自检退出码。

#### Scenario: 生产机未装静态检查器

- **WHEN** 在未安装静态检查器的机器上运行自检
- **THEN** 自检打印跳过提示
- **AND** 其余检查项照常执行，整体退出码不受该项影响

#### Scenario: 开发机已装静态检查器且发现问题

- **WHEN** 在已安装静态检查器的机器上运行自检，且检查器报出问题
- **THEN** 自检以非零码退出并输出检查器的报告

### Requirement: 已被订正的结论不得复活

提交前自检 MUST 以退出码拦截**已登记的过期论断**再次出现在代码或文档中。
登记清单 MUST 以数据形式集中，每条附订正日期与订正依据。
明确标注为「已订正 / 过期结论」的说明文字 MUST NOT 被误伤。

理由：跨文件的重复**论断**（不是重复代码）没有任何别的工具抓得到——它们措辞各异、
散在注释与文档里，订正一处不会让其余几处报错，只会让它们静默地继续指导代码。
2026-09-05 实测：一条 09-01 已订正的结论在仓库里留了三份拷贝，修了两处漏了第三处，
而漏掉那处最贵——该处跑了反扫器、拿到结果后在渲染时扔掉。

⚠️ 能力边界 MUST 被写明：本项只认登记在册的论断，认不出未登记的。
它防的是「同一条已知错误结论再次复活」，MUST NOT 被理解为「能发现新的错误结论」。

#### Scenario: 已登记的过期论断出现在代码中

- **WHEN** 某文件出现登记清单中的过期论断，且未标注为已订正
- **THEN** 自检 MUST 失败并指出文件与行号

#### Scenario: 说明旧结论的文字

- **WHEN** 某处引用过期论断是为了说明它已被订正
- **THEN** MUST NOT 报出——判据是该行是否带有订正标记

#### Scenario: 文档与代码同等对待

- **WHEN** 过期论断出现在随仓库分发的文档中
- **THEN** 与出现在脚本中同等处理——2026-09-05 的三份拷贝里就有一份在文档
