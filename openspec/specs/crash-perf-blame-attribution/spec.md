# crash-perf-blame-attribution Specification

## Purpose
按崩溃归因方（自家代码 / 三方 SDK / 系统）呈现事件与影响面分布，让「该谁接」这个问题在报告里有答案；同时约束该维度不得被用作根因断言。

## Requirements

### Requirement: 归因分布的采集与呈现

报告 MUST 按崩溃数据源提供的归因方标识聚合事件数与受影响安装数，并在报告中呈现该分布。

归因方 MUST 与被归因的代码库一并呈现——只给归因方会丢掉「是哪个库」这个可定位信息，只给库会丢掉「是谁的代码」。

#### Scenario: 存在归因信息

- **WHEN** 窗口内的崩溃事件带有归因方标识
- **THEN** 报告呈现各归因方的事件数与受影响安装数
- **AND** 一并呈现对应的代码库

#### Scenario: 归因信息缺失

- **WHEN** 部分事件没有归因方标识
- **THEN** 这些事件被归入一个显式的「未归因」类目
- **AND** MUST NOT 被静默丢弃或摊入其它类目

### Requirement: 归因方不得被当作责任判定

报告 MUST NOT 因某事件的归因方是系统或三方而断言「与自家代码无关」。

理由：归因方标识的是**崩溃栈中被判定为责任帧的那一帧属于谁**，不是「谁触发了这次崩溃」。实测存在归因方为系统、而被归因代码库正是自家包名的情形——那是系统帧被自家代码调用。

#### Scenario: 归因方为系统或三方

- **WHEN** 某批事件的归因方为系统或三方
- **THEN** 报告呈现该事实与对应代码库
- **AND** MUST NOT 表述为「非自家问题」或「无需处理」

#### Scenario: 需要判断责任归属

- **WHEN** 读者需要判断某崩溃该由谁处理
- **THEN** 报告提供归因分布作为线索，并指向承担分析职责的产物
- **AND** 不在高频呈现层给出结论
