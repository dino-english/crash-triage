> 分层原则与依赖方向见 [CLAUDE-架构与数据口径.md](CLAUDE-架构与数据口径.md)「分层与依赖方向」；本文补的是「哪里还没分、值不值得分」。

## 「长」的三种成因要分开处理

⛔ **把三者混为一谈是这类重构失败的主因**——真重复该合并，单点复杂该留在原地，刻意不拆的该继续不拆。

### ① 真重复（该收口，收益确定）

**同一份 SQL 被两个脚本各自包装了一遍**，实测 8 份：

| SQL | L1 引用 | L2 引用 |
|---|---|---|
| `crash-rate.sql` | 3 | 3 |
| `crash-dimensions.sql` | 4 | 1 |
| `latest-versions.sql` | 2 | 2 |
| `crash-blame.sql` | 1 | 2 |
| `crash-error-types.sql` | 1 | 1 |
| `perf-traces / screens / network.sql` | 各 1 | 各 1 |

L1 叫 `qdim` / `qc`，L2 叫 `ver_dim` / `ver_crash` / `ver_blame` / `ver_etypes` / `perf_row`——**名字不同、占位符替换逻辑相同**。

同类还有：
- **CSV 解析**：L1 走 `md_csv_table` 的 Python `csv.reader`，L2 走 `csv2tsv`（2026-08-24 新加）。两份实现、同一个目的。⚠️ 分歧期间 L2 用 `awk -F,` 裸切，把 1 个事件渲染成了 11。
- **维度 / 归因渲染**：L1 `dim_csv` + `blame_csv`，L2 `dims_md` + `blame_md`。同源数据两套渲染器。
- ~~`day_ago`~~ 已于 2026-08-24 收口到 `bin/lib.sh`（被 `check-scripts` 第 3 项当场拦下）。

### ② 单点复杂（不是重复，拆了也不变短）

`build_report_xml`（314 行块的主体）、`collect_window`（239 行块的主体）——它们长是因为**要处理的情况本身多**（四种缺数状态 × 两端 × 两版本 × 三类事件）。拆成小函数只会把同样的复杂度摊到更多文件，还多出参数传递的出错面。

⚠️ 判据：拆分后**调用点是否变少**。变少才是抽象，只是搬家就不是。

### ③ 刻意的 Non-goal（前提仍成立，继续不拆）

CLAUDE.md 记着：

> ⛔ 渲染层拆分与表名参数化是**刻意的 Non-goal**，不是遗漏

理由是「三种渲染共享 `cell()` / `delta_of()` 的判定，拆分需要逐段对照，与零行为变更的验收目标冲突」。

**2026-08-24 复核：前提仍然成立。** 三种渲染确实共享判定，且 `cell()` 有 100 行的分支逻辑；抽取时任何一个分支漏对照都会静默产出错误数字，而这类错误**没有测试能抓**（没有单元测试框架，验收靠冻结缓存 diff）。

⚠️ 但记录一条修正：Non-goal 的理由是**风险**，不是「拆了没用」。等价性验收协议（`bin/test/`）成熟之后，风险是可以被压下来的——真要拆，前置条件是**先有一组覆盖三种渲染的冻结缓存基线**，而不是直接动刀。

## 检测盲区

`check-scripts.sh` 第 3 项只抓**同名**函数出现在多个文件。上面 ① 里的重复**全部改了名**，因此：

- ⛔ `qdim` vs `ver_dim`、`md_csv_table` vs `csv2tsv`、`dim_csv` vs `dims_md` —— **lint 一个都抓不到**
- ⛔ prompt 与 bash 的重复（`FACT_CACHE_POLICY`）跨语言，更抓不到；唯一手段是产物断言 `assert-fact-cache.sh`

**没有工具能替你发现改了名的重复。** 加 SQL 包装或渲染函数前，先 `grep -n '<sql文件名>' bin/*.sh` 看另一条链路有没有等价物。

## 实证：2026-08-24 往 crash-weekly.sh 加一个特性的代价

加「TOP N 下钻」一项，需要在**相隔数百行的三处**改动：常量区（`DD_TOP_N`）、取数区（`dd_fetch`）、渲染区（`dd_block`）。实测连踩三次同类错误：

| 错误 | 表现 | 退出码 |
|---|---|---|
| 常量定义在使用点之后 | `DD_TOP_N: unbound variable` | **0**（被 EXIT trap 吞，见 F24） |
| 函数定义在使用点之后 | `dd_fetch: command not found` 被 `\|\| true` 吞 | 0（空产物） |
| SQL 加列后 awk 字段号没同步 | `页面：13 SplashActivity/17（0%）` 值与计数颠倒 | 0（坏数） |

⚠️ 三者共同点：**都不报错，或报错被吞**。这不是「小心一点就能避免」——900 行单文件里，声明与使用之间隔着几百行时，顺序正确性没有任何工具在守。

**这条直接支持优先级 2（SQL 包装收口）**：它把取数逻辑集中到一处，声明与使用的距离从「几百行」压到「同一个文件的相邻几行」。

## 优先级

按「收益确定性 ÷ 静默出错风险」排，**不是按代码行数排**。

| # | 动作 | 收益 | 风险 | 前置 |
|---|---|---|---|---|
| 1 | **CSV 解析收口**到 `bin/lib/`，两条链路共用 | 消除一个**已经造成过错误数字**的分歧 | 低——纯函数，输入输出可逐字节比对 | 无 |
| 2 | **SQL 包装收口**：`bin/lib/query.sh` 提供 `q_dim` / `q_crash` / `q_blame` / `q_etypes` / `q_perf`，两条链路各自 source | 8 份 SQL 的占位符替换只剩一份；改窗口/加占位符不会只改一半 | 中——L1/L2 窗口天数不同，签名要把窗口作参数，**不能沿用任一方的默认值** | 冻结缓存基线 |
| 3 | **维度/归因渲染收口**：一份数据结构 → 两种输出（md / 卡片行） | 消除同源两渲染器 | 中 | 同上 |
| 4 | 采集层 `collect_*` 下沉 | 编排层瘦身 ~239 行 | 中高——写全局变量，副作用面大 | 同上 |
| 5 | 三种渲染拆分 | 编排层瘦身 ~726 行 | **高**（见 ③） | 三渲染冻结基线 + 逐分支对照 |

⚠️ **1 和 2 就能拿走大部分收益**，且都是「消除已经咬过人的分歧」而非美化。4 和 5 属于「代码更好看」，在没有单元测试的 bash 仓库里性价比低。

## 动手前必须知道的约束

- ⚠️ **函数不跨进程**。核心层要在**每个**子脚本里各自 `.` 一次——新增共享文件时，8 个子脚本的加载行都要检查（见架构文档「跨进程边界」）。
- ⚠️ **核心层不许依赖全局**，要能在 `env -i` 空环境里调用。`collect_*` 现在写全局变量，下沉前得先改成参数进、stdout 出。
- ⛔ **核心层缺失直接失败不退化**——阈值判定与格式化只有一份实现，退化版本会静默产出错误数字。
- ⚠️ 验收走 [eqv-check](../.claude/skills/eqv-check/SKILL.md)：冻结缓存 + 三层产物 diff。**活数据上 diff 永远不为空**，不冻结等于没验。
- ⚠️ `check-scripts.sh` 是**九项**且**递归**扫 `bin/**/*.sh`——新目录会自动纳入。
