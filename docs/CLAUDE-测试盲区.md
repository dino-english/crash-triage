# 测试盲区：为什么「测过了」还会在跑批时炸

> 2026-08-24 复盘。当天我在一条链路上连续引入 7 个 bug，**每一个改动前都做了函数级测试**，
> 却仍有 5 个要等到跑批（5–15 分钟）甚至由使用方读产物才发现。
> ⛔ 结论不是「测得不够仔细」——是**测试方法有三个结构性盲区**，再仔细也堵不上。

## 二、三个结构性盲区

### 盲区① 抽函数出来测 = 把「顺序」测没了

典型夹具：

```bash
{ echo '常量=值'; sed -n '/^my_fn() {/,/^}/p' script.sh; echo 'my_fn 参数'; } | bash
```

⛔ 这把函数从它在文件里的位置**摘了出来**，于是「定义在使用点之后」这类错误在夹具里**永远重现不了**——夹具里它总是先定义后使用。

当天三次同类错误全部源于此。⚠️ 这不是夹具写得糙，是**这种测法在原理上看不见顺序**。

**解法**：顺序是静态属性 → 用静态检查（`bin/test/lint-order.py`，check-scripts 第 7 项），⛔ 不要指望动态测试。

### 盲区② 只测「坏输入会红」，不测「好输入不红」

给 `q_render` 加多传检测时，我塞了违规样本确认变红就收工。而它对**正常设计**（通用包装固定传一整套占位符）也报——当轮跑批就给使用方发了误报告警卡。

⚠️ 一个乱红的检查比没有检查更危险：**它训练人忽略告警**。

**解法**：每加一项检查做**双向测试** ①违规样本变红 ②**当前全量代码不红**。已写进 `check-scripts.sh` 文件头。

### 盲区③ 夹具的 shell 设置与生产不同

| | 生产（`crash-*.sh` 头部） | 我的典型夹具 |
|---|---|---|
| `set -e` | ✅ | ❌ |
| `set -u` | ✅ | ✅ |
| `pipefail` | ✅ | ✅ |
| `errtrace` + ERR trap | ✅ 发告警 | ❌ |

F31 就死在这里：`grep -o` 无匹配返回 1，**在夹具里只是个被忽略的退出码，在生产里是一张告警卡**。
我测了 `rc=0`（函数返回值确实是 0），但没测「过程中有没有命令返回非零踩到 ERR trap」。

**解法**：`bin/test/harness.sh`——让函数级测试跑在**与生产相同的 shell 设置**下，ERR trap 触发即判失败。

### 盲区④ 卡片的**列宽**只有真发一张才验得出

DRY RUN 与日报 markdown 预览渲染的是同一批数据、同一套列，看上去完全正常——但 CardKit 表格
**总宽固定、按列数比例分配**，截断只发生在飞书客户端的真实渲染里。

**发生**：2026-08-27 把卡片从每端 2 列改成 3 列（7 列表），DRY RUN 一切正常，实发第一张就被截。

**怎么验**（不必重跑整条链路）：dry-run 已经把卡片写到 `$STATE/publish/card.json`，直接单发一张：

```bash
. "$STATE/local.env"   # 开发机 CRASH_REPORT_CHAT_ID 已是 ou_ 私聊，不是日报群
lark-cli --profile crash-triage im +messages-send \
  --user-id "$CRASH_REPORT_CHAT_ID" --msg-type interactive \
  --content "$(cat "$STATE/publish/card.json")" \
  --idempotency-key <每次换> --as bot --format json
```

不写 state、不建文档、不碰归档。⚠️ 返回的 `chat_id` 是 p2p 会话（**也是 `oc_` 开头**），
与日报群 `oc_655033f1…` 不同，别看到 `oc_` 就以为发错了。

⛔ **这张卡的三个按钮是死的，发之前先说一声**：`__DETAIL_URL__` / `__INDEX_URL__` / `__FOLDER_URL__`
由 `deliver.sh` 在**飞书文档建好之后**才回填（`deliver.sh:381-388`），dry-run 产出的 `card.json` 里还是占位符原文。
验列宽不受影响（版面与文案照常渲染），但收卡的人点「详情」会打不开。
⚠️ 要连按钮一起验，只能走真实投递——那会建文档、写归档，是另一件事。

⛔ 压缩文案时**只压卡片、文档保持完整**，且⛔ **不得为了省宽度砍掉有记录的口径标注**
（样本量括注、两端窗口标注这类）——那不是排版问题，是口径问题。

## 三、判据（动手前问自己）

1. 这个改动的错误**会以什么形式表现**？值不对（动态测试能抓）/ 顺序不对（只有静态检查能抓）/ 退出码不对（要 harness）/ 文案与实况不符（只有人读产物能抓，见 F29）
2. 我的夹具**有没有生产的 shell 设置**？
3. 我有没有测**正常路径不报错**，而不只是**异常路径报错**？
4. 我的断言是**正向**的吗（必须出现 X）还是只是「没崩」？⚠️ 空输出常常被当成合法。
5. 我新加的断言**真的在 gating 吗**？⚠️ 追加到 `h_summary` 之后会照常打印 ✅ 却不进统计（F36）。判据：故意植入一个违规样本，看退出码变不变。
6. 我这次验收**看到的东西，是不是就是要发出去的东西**？⚠️ 同一份数据有两个渲染点时，预览可能来自没被改的那个（F35）；卡片列宽则连正确的预览也验不出（盲区④）。

## 四、仍然抓不到的（诚实登记）

- **F29 类**：文案与实况自相矛盾（原因写"显式跳过"、建议写"等额度恢复"）。两行各自都对，错的是组合。⛔ **没有工具能抓**，只有人读产物。
- **F18 类**：模型路径产物的非确定性——冻结缓存冻得住 bq，冻不住模型。
- **跨轮潜伏**：`WOW_CUT` 那种"首轮不进分支、第二轮才炸"。静态检查能抓这一个，但同类未必都能。
